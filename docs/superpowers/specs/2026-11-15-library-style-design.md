# 曲库主页与全屏播放器样式设计

日期为 2026-11-15。人类已确认 B 全屏展开方向及桌面、手机布局，并审阅书面方案，授权继续曲库主页实施规划。

## 1. 设计目标与归属

围绕“曲库直接选歌、跨页持续播放、点击封面展开播放器”的使用路径，形成曲库主页、底部播放栏及全屏播放器的共同视觉方案。交付内容包括布局、配色、排版、展开与收起、响应式和状态呈现要求。

功能归属沿用 LIB-01 曲库主页、PLAY-01 全局播放、PLAY-02 队列与模式。歌词作为 PLAY-03 后续任务记录，其数据来源和同步能力在对应功能设计中确定。各代码切片由人类选择后分别规划与验收。[曲库主页任务书](../../tasks/library-homepage.md)

## 2. 人类确认记录

以下决定来自本次样式设计对话及浏览器预览确认。

| 区域         | 已确认决定                                                     |
| ------------ | -------------------------------------------------------------- |
| 顶部栏       | 主要提供音乐、搜索和个人中心入口                               |
| 曲库侧栏     | 提供收藏和歌曲管理入口，管理入口依据 ADMIN 登录身份呈现        |
| 曲库内容     | 列表直接展示歌曲基本信息，并可直接发起播放                     |
| 底部栏       | 展示当前播放歌曲，提供播放控制和播放模式调整                   |
| 展开入口     | 点击底部栏的歌曲封面，播放器向上展开                           |
| 桌面展开方向 | 选择 B 全屏视图，覆盖顶部业务导航                              |
| 桌面播放器   | 封面居左、歌词居中、播放列表居右，底部控制常驻                 |
| 手机曲库     | 收藏和管理通过左侧抽屉访问，顶部提供音乐、搜索与个人中心入口   |
| 手机播放器   | 封面与歌词上下排列，播放列表通过右侧抽屉访问                   |
| 视觉方向     | 沿用嫩叶绿、白色内容面及墨绿文字，以列表和歌曲内容形成视觉重心 |

本轮比较过“顶部常驻、左侧栏切换为队列”的 A 方案和“全屏上滑、右侧队列”的 B 方案。人类明确选择 B，随后确认手机布局。

## 3. 配色与排版

### 3.1 核心配色

| 名称       | 色值      | 用途                               |
| ---------- | --------- | ---------------------------------- |
| 白色内容面 | `#FFFFFF` | 顶部、曲库内容与底部播放栏         |
| 浅绿背景   | `#EEF3E6` | 全屏播放器主要背景                 |
| 嫩叶绿     | `#C8DDA4` | 品牌关联、封面缺省图的参考色       |
| 操作绿     | `#62894B` | 播放按钮、进度和功能图标           |
| 墨绿文字   | `#30492F` | 正文、当前歌曲、当前歌词与队列文字 |
| 次级文字   | `#607153` | 艺术家、专辑、时长与普通歌词       |

边线沿用 `#D8E2CE`。侧栏及当前行使用同一绿色体系的浅色层次，选中状态同时通过位置、字重或标记表达。文字在实际背景上核对对比度，队列中的次级文字也使用墨绿，以维持浅绿选中底上的清晰度。[现有主题](../../design/theme.md)

### 3.2 字体与信息层级

- 品牌与曲库标题沿用现有系统宋体方向，正文和操作使用项目现有系统无衬线字体。
- 桌面曲库标题参考 28—29px，歌曲行正文参考 12—14px，通过列对齐建立信息层级。
- 桌面歌词参考 17px，当前行参考 20px。手机歌词参考 14px，当前行参考 17px。普通行与当前行通过字号、字重和文字颜色区分。
- 歌名、艺术家和专辑默认左对齐。桌面歌词形成独立阅读列，手机歌词居中排列。时长使用稳定数字宽度。
- 长歌名与次级资料按可用空间省略，并提供可访问的完整文本读取方式。手机保留“歌名／艺术家与专辑／时长”的信息层级。

## 4. 桌面曲库

```text
┌──────────────────────────────────────────────────────────────┐
│ 风与叶     音乐       搜索歌曲、艺术家、专辑        个人中心 │
├────────────┬─────────────────────────────────────────────────┤
│ 我的收藏   │ 曲库                                      排序 │
│ 歌曲管理   │ 歌曲与封面       艺术家       专辑       时长  │
│            │ 歌曲行与收藏操作                              │
│            │ 分页                                          │
├────────────┴─────────────────────────────────────────────────┤
│ 封面／当前歌曲   上一首／播放／下一首／进度   模式／音量   │
└──────────────────────────────────────────────────────────────┘
```

顶部、侧栏和播放栏形成稳定的业务框架。原型以顶部约 68px、侧栏约 184px、底部约 92px 为比例参考，具体 CSS 随窗口和真实内容调整。主要留白放在列表四周，歌曲行保持连续对齐。

曲库主区承担列表滚动。排序和分页使用现有服务端契约允许的字段与范围。搜索框呈现歌名、艺术家和专辑的搜索用途，搜索触发、查询状态与 URL 的关系由 LIB-01 业务设计确认。

当前播放行使用浅绿背景和播放标记。封面、歌名、艺术家、专辑、时长和收藏操作构成一行的视觉层级。普通用户与管理员的曲库内容范围均为已发布歌曲，管理入口按本次登录身份显示。[列表契约](../../api/track/list-tracks.md)

歌曲管理入口、页面和管理接口要求本次以 ADMIN 身份登录。管理员选择 USER 身份登录时遵循普通用户规则，菜单和路由守卫依据本次会话角色判断。[曲库任务书](../../tasks/library-homepage.md)

## 5. 底部播放栏

桌面左侧展示封面、当前歌名、艺术家和收藏操作，中部放上一首、播放与暂停、下一首及进度，右侧放播放模式与音量。播放模式使用明确的中文名称，顺序播放、单曲循环和随机播放属于 PLAY-02。

歌曲封面承担展开入口，鼠标悬停和键盘聚焦时显示展开提示。播放、拖动进度、调整模式和音量分别具有独立操作区域。

底部栏与全屏视图消费同一份当前歌曲、播放进度和模式状态。展开、收起及业务页面导航都通过共享播放状态衔接。无当前歌曲时呈现选歌引导，相关控制按可操作状态呈现。播放加载、暂停、失败和恢复状态在 PLAY-01 中形成完整交互与测试。

## 6. 桌面全屏播放器

```text
┌─────────────────────────────────────────────────┬────────────┐
│ 收起                                            │ 播放列表   │
│                                                 │            │
│   专辑封面          歌词阅读区                  │ 当前歌曲   │
│                     当前歌词行强调              │ 后续歌曲   │
│   歌名／艺术家                                  │            │
├─────────────────────────────────────────────────┴────────────┤
│ 当前歌曲         播放控制与进度                 模式／音量 │
└──────────────────────────────────────────────────────────────┘
```

展开层从底部向上覆盖业务内容及顶部导航，底部播放控制继续可操作。原型展开约 520ms，使用平缓减速。收起入口位于左上角，通过逆向位移表达回到原浏览上下文。减少动态偏好下直接呈现最终状态。

封面与歌曲资料位于左部，歌词位于中部，播放列表常驻右侧。大封面的尺寸同时受内容宽度与可用高度约束。歌词和播放列表各自具备明确的滚动区域，长内容下维持底部控制与收起入口可达。

这里的“播放列表”指当前播放队列，队列来源、跨分页范围、重复项和随机范围由 PLAY-02 设计确认。桌面侧栏当前项使用浅绿选中底，名称与艺术家分别排列。

收起后恢复原页面的查询条件与浏览位置。界面内收起、Esc、焦点恢复与抽屉关闭作为播放交互的验收项。URL、浏览器前进后退与展开状态的绑定规则在 PLAY-01 中确认。

## 7. 手机布局

### 7.1 曲库与导航

顶部保留品牌、菜单、音乐、搜索和个人中心的可访问入口。收藏与歌曲管理通过菜单打开左侧抽屉。搜索入口展开顶部输入区，主内容随之调整可用空间。

歌曲行将艺术家与专辑合并为次级信息，时长位于右侧。顶部、主区和底部各自分配空间，列表在中间区域滚动。底部栏压缩为歌曲信息与播放控制、模式及进度的组合，长歌名按可用宽度省略。

### 7.2 全屏播放器与播放列表

```text
┌───────────────────────────┐
│ 收起             播放列表 │
│                           │
│          封面             │
│       歌名与艺术家        │
│                           │
│        歌词阅读区         │
│      当前歌词行强调       │
├───────────────────────────┤
│ 当前歌曲      播放控制    │
│ 模式              进度    │
└───────────────────────────┘
```

展开后使用封面在上、歌词在下的纵向结构。播放列表入口位于右上，打开右侧抽屉并显示遮罩。抽屉提供明确关闭入口，遮罩与 Esc 优先关闭抽屉，随后可收起播放器。

抽屉和展开视图使用清晰层级，背景区域在相应状态下停止接收交互。关闭抽屉后恢复对应入口焦点，收起播放器后恢复封面入口焦点。短屏、横屏、放大及长歌词按可用空间滚动。

手机原型展示了紧凑播放控制，手机音量入口与浏览器媒体能力的关系由 PLAY-01 在实现设计中确定。

## 8. 状态与数据职责

| 状态                       | 样式与交互要求                                                 |
| -------------------------- | -------------------------------------------------------------- |
| 曲库读取中                 | 在列表区域呈现加载反馈，导航和播放状态各自保持可用             |
| 曲库为空                   | 内容区呈现清晰空态，提供符合当前权限的操作引导                 |
| 搜索无结果                 | 呈现搜索结果状态并支持修改或清除查询                           |
| 列表读取失败               | 显示安全错误文案和重试入口，搜索限流按后端返回的恢复时机反馈   |
| 封面缺失或加载失败         | 使用同一视觉体系的缺省封面                                     |
| 播放加载或失败             | 底部栏和展开视图体现相同播放状态，恢复操作归属 PLAY-01         |
| 歌词加载、无歌词或读取失败 | 歌词阅读区分别呈现加载、暂无歌词和可恢复错误状态               |
| 歌曲被归档或删除           | 按歌曲、播放、收藏接口的最新响应反馈，并提供刷新或恢复操作     |
| 当前会话失效               | 经既有会话管理完成清理与安全登录跳转，同时释放该会话的媒体资源 |

业务框架承载顶部、侧栏、主页面、底部栏和全屏播放视图。Pinia 统一管理跨页播放状态，各页面保留自己的查询和展示状态。资源读取经 `src/api/` 或经过确认的媒体传输封装完成，播放器和页面通过共享状态与明确事件协作。

歌词区域的视觉层次已确认，当前 `docs/api/` 需要补充有效的歌词来源与消费契约。PLAY-03 据此确认格式、时间信息及同步规则。音频授权与曲库初始收藏状态分别沿用原有任务依赖。[音频契约](../../api/track/stream-track.md)与[任务依赖](../../tasks/library-homepage.md)
