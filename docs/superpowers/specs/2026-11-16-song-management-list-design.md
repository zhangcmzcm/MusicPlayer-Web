# MGMT-01 管理员歌曲列表设计

设计日期为 2026-11-16。管理模块整体流程与六个切片的组织方式已由人类确认，本文定义首个可独立验收的管理列表切片。2026-11-17 人类通过书面方案并授权编写实施计划。

## 1. 目标与切片边界

为当前以 ADMIN 身份登录的管理员提供真实歌曲管理入口、全部状态浏览、状态筛选、搜索、排序、分页和读取恢复。管理员从曲库侧栏进入管理列表，列表呈现共享曲库中当前授权范围内的数据。

| 能力                         | 交付归属       |
| ---------------------------- | -------------- |
| 歌曲管理导航、列表与查询恢复 | 本切片 MGMT-01 |
| 多文件导入页与批次状态       | MGMT-02        |
| 草稿表单与保存、版本恢复     | MGMT-03        |
| 发布操作                     | MGMT-04        |
| 归档操作                     | MGMT-05        |
| 彻底删除                     | MGMT-06        |

列表的批量导入、编辑及状态变更入口与对应真实流程同时交付。首个切片提供可独立使用的管理读取能力，后续菜单和操作按实际功能接入。[歌曲管理任务书](../../tasks/song-management.md)

## 2. 决策来源与当前基线

- 人类确认 A 方案，管理列表、独立批量导入页与草稿编辑页共用业务框架。
- 管理列表默认全部状态、最近加入，提供搜索、排序、分页，返回时恢复原查询。
- DRAFT、PUBLISHED、ARCHIVED 分别对应任务书的合法操作矩阵。
- 当前会话角色来自 `auth.session.user.role`，ADMIN 账户以 USER 身份登录时按普通用户处理。
- 配色、字体、顶部、侧栏、手机抽屉采用已确认的曲库视觉方向，具体间距和响应式 CSS 按实际内容验证。

代码与文档核对基线为 `main / b735d0f7f797d7375efd477602ab064049a0fa96`。工作区原有列表契约搜索更新和三份收藏契约均属于人类提供的只读依赖。

相关依据为 [曲库样式设计](2026-11-15-library-style-design.md)、[曲库功能说明](../../features/library.md)、[列表契约](../../api/track/list-tracks.md)、[封面契约](../../api/track/get-track-cover.md)及项目 AGENTS.md 的权限、响应消费和验证规则。

## 3. 路由、导航与权限

列表地址为 `/admin/tracks`，路由名采用 `track-management`，作为现有 BusinessLayout 的受保护业务子页面。路由显式声明 `requiresAuth: true`、`roles: ['ADMIN']` 与侧栏 navigation 元信息，标签为“歌曲管理”。

现有 BusinessLayout 按实际路由和当前角色生成桌面侧栏、手机左抽屉。ADMIN 在曲库和管理页均可看到真实管理入口，当前管理页高亮对应导航，手机选中后收起抽屉并进入页面。后续导入与编辑页的导航归属由各自切片接入。

| 进入条件           | 设计行为                                                                                         |
| ------------------ | ------------------------------------------------------------------------------------------------ |
| 未认证或已过期     | 经现有认证守卫进入登录，保留安全站内目标                                                         |
| 当前 ADMIN         | 允许进入并按管理查询读取数据                                                                     |
| 已认证 USER        | 角色守卫提示无权限。有当前有效业务页面时保持该页面，首次直达或登录回跳的角色拒绝以曲库为安全落点 |
| 后端读取返回 403   | 管理列表显示安全无权限反馈，提供返回曲库入口                                                     |
| 当前受保护请求 401 | 采用 Token 与 revision 的会话归属判断，清理当前会话并安全进入登录                                |

角色校验采用现有守卫。实施时需核对首次管理直达和登录回跳被拒的落点，避免将角色拒绝仅视为已有页面内的普通导航取消。守卫负责导航，列表取数由页面流程承担。实际数据授权由后端执行。

## 4. 管理列表布局

桌面继续使用白色内容面、浅绿侧栏、墨绿文字及宋体页面标题。标题为“歌曲管理”，状态筛选为“全部、草稿、已发布、已归档”。排序和页大小与筛选共同呈现，搜索使用业务顶部已有搜索区域。

表格连续展示序号、封面与歌名、艺术家、专辑、状态和时长。状态使用中文标签与语义颜色共同表达。数据统计采用本次筛选响应的真实总数，分页位于列表末尾。createdAt 仅作为排序字段消费。

手机使用左侧导航抽屉。歌曲、艺术家及专辑在有限宽度内合并排版，状态保留清晰中文标记，时长维持可读。长内容省略时保留完整文本读取方式，排序、页大小与页码均可键盘操作，主内容纵向滚动。

本切片的表格列依据当前响应字段，后续可操作流程接入时增加对应行操作。页面挂载或已提交查询变化时设置清晰标题焦点，异步响应完成保留用户当时的操作焦点。复用现有减少动态偏好规则。

## 5. 查询模型与交互

查询模型为 q、status、page、size、sort。status 缺省代表全部状态，单状态取 DRAFT、PUBLISHED 或 ARCHIVED。“全部”在业务请求中通过省略 status 表达。

| 项目                   | 规则                                                          |
| ---------------------- | ------------------------------------------------------------- |
| 初始条件               | q 为空、全部状态、page=0、size=20、sort=createdAt,desc        |
| URL                    | 保存已提交的 q、status、page、size、sort，序列化省略默认值    |
| 搜索草稿               | 输入保留为表单草稿，Enter／按钮提交，组合输入期间阻止提交     |
| 原始关键词             | 原样传输，包含首尾空白的码点及重复词计数按契约处理            |
| 清空关键词             | 恢复对应状态下的普通列表                                      |
| 状态、排序、页大小变化 | 回到第 1 页读取                                               |
| 排序                   | id、title、artistName、createdAt 的 asc／desc，共八个有效选项 |
| 页大小                 | 1—100，默认 20                                                |
| 页码                   | 0 基请求，1 基显示，page × size ≤ 10000                       |
| 相同查询重交           | 手动刷新，pending 中合并相同请求                              |
| 前进、后退与刷新       | 从 URL 恢复已提交查询和表单显示                               |
| 非法已知 URL 参数      | 显示客户端查询错误，提供恢复默认条件，停止该次无效读取        |

已知参数的重复值、非法类型和非法范围按客户端导航规则拒绝，无关 URL 字段按现有查询消费规则忽略。纯空白关键词与空关键词分别按契约非法搜索和普通列表处理。

搜索每账户额度与 USER／ADMIN 身份共享。429 使用有效 Retry-After 反馈剩余等待时间，携带关键词的读取在冷却期间等待手动恢复。清空关键词仍可读取对应状态的普通列表。

下一页要求服务端 hasNext 且下一页乘积符合深分页上限，上一页要求 page 大于 0。页码输入上限为 floor(10000 / size) + 1。合法越界空页保留真实统计与请求页，提供回到第一页。

## 6. 接口与职责

| 单元                      | 职责                                                         | 输入、输出与依赖                                                 |
| ------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------- |
| 管理 API 封装             | GET `/api/v1/tracks`，按全部或单状态读取，精确消费 JSON Long | 查询与取消信号输入，标准页输出，依赖统一 HTTP 与现有精确解析逻辑 |
| 查询工具                  | 解析、校验及序列化管理 URL 查询                              | q、status、page、size、sort 与客户端查询错误                     |
| 列表 composable           | pending／error、重试、搜索冷却、请求取消及过期响应控制       | 消费查询与当前会话，输出当前页和反馈状态                         |
| 管理查询组件              | 搜索、状态、排序与页大小                                     | props 接收当前查询与 pending／冷却，通过事件提交条件             |
| 管理表格组件              | 歌曲资料、状态、加载／空／错误与分页                         | props 接收页、查询和反馈，事件请求翻页或重试                     |
| 管理页面                  | URL 与事件编排、标题焦点与返回曲库                           | 消费 router 与 composable，组织展示组件                          |
| 既有业务框架与 TrackCover | 实际导航、抽屉、鉴权图片与缺省封面                           | 路由元信息与会话角色，歌曲 ID 与封面存在性                       |

曲库请求的业务范围为 PUBLISHED，管理读取的范围为全部或指定状态，API 层按各自用途封装。管理实现需复用已有 Long 解析、时长、搜索规则、错误映射和资源生命周期，保持各调用入口的范围明确。

查询变化取消旧读取，响应写入同时核对请求序号、信号、会话对象与 revision。页面私有查询和页数据由页面流程持有，跨页面的导入批次状态由 MGMT-02 管理。封面按精确歌曲 ID 构造已知业务地址获取 Blob，资源切换、解码失败和卸载释放旧 Object URL。

## 7. 字段消费与校验依据

| 字段或判断        | 依据                                         | 消费与恢复行为                                                                                       |
| ----------------- | -------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 请求 q            | 列表“查询参数／关键词匹配”                   | 非空原始值 1—100 Unicode 码点，White_Space 拆分为 1—5 词。空字符串省略，纯空白、数组与超限拒绝       |
| 请求 status       | 列表“接口与权限／查询参数”，本轮全部默认决定 | 省略表示全部，单值仅 DRAFT／PUBLISHED／ARCHIVED，空值、数组与未知值拒绝                              |
| page／size／sort  | 列表“查询参数”                               | 非负整数页、页大小 1—100、乘积至多 10000，合法单字段与方向。接受合法整数的正号及前导零写法           |
| items             | 列表“成功响应”                               | 必需数组，空数组合法，异常关键结构显示读取错误                                                       |
| id                | 列表 Long 与封面路径                         | 正整数 Long，最大 9223372036854775807，保持精确十进制字符串，异常关键 ID 显示读取错误                |
| status 响应       | 列表状态枚举与本次筛选范围                   | 全部查询接受三个合法状态，单状态查询要求符合对应范围。缺失、null、未知枚举或超出本次范围显示读取错误 |
| title／artistName | 列表展示字段及项目响应恢复规则               | 合法字符串按原值显示，异常缺失／null／类型与空值安全降级为未命名歌曲／未知艺术家                     |
| albumName         | 列表合法可空字段                             | null 显示未标注专辑，异常缺失或类型同样安全降级                                                      |
| durationMs        | 列表 Long 或 null 及现有格式化               | 精确保留合法 Long，未知或无法格式化值显示未知时长，0 与最大 Long 保持精度                            |
| cover             | 列表 Object 或 null、封面契约                | null 使用缺省图，对象存在时按 ID 请求。图片错误回退，元数据中的 URL 作为资料消费                     |
| 响应分页字段      | 列表“成功响应”                               | page／size 回显本次请求，totalElements／totalPages 保持非负 Long 精度，hasNext 必需 boolean          |
| 未知响应字段      | AGENTS 响应消费规则                          | 忽略不影响当前用途的新增字段                                                                         |
| 请求和会话有效性  | AGENTS 客户端生命周期与安全规则              | 取消和忽略过期结果，当前受保护 401 才触发当前会话失效                                                |

响应校验关注本次读取、授权范围和安全操作所需字段，展示异常按用途降级。查询错误使用本地客户端错误表达，业务失败继续消费稳定后端 code。

MGMT-01 的消费字段取自现行列表与封面契约。草稿 version 的读取扩展属于 MGMT-03 的明确开工前置，详见[管理任务书](../../tasks/song-management.md#version-读取前置条件)。

## 8. 状态与恢复

| 状态                | 展示与操作                                         |
| ------------------- | -------------------------------------------------- |
| 读取中              | 列表区域反馈加载，旧页资料清除，导航和查询输入可用 |
| 全部为空            | 显示暂无歌曲与真实统计                             |
| 单状态为空          | 显示当前状态暂无歌曲                               |
| 搜索无结果          | 提示调整或清空关键词，保留状态筛选                 |
| 合法空页            | 显示当前页暂无歌曲、真实总数与回到第一页           |
| 查询无效            | 恢复默认条件入口                                   |
| 列表网络／超时／5xx | 集中安全文案与手动重试                             |
| 搜索限流            | 倒计时与手动恢复，普通列表可读取                   |
| 图片失败            | 缺省图，当前歌曲文字资料继续展示                   |
| 403                 | 无权限反馈与真实曲库入口                           |
| 当前会话 401        | 现有统一失效流程与安全登录回跳                     |
| 旧请求、旧会话响应  | 按请求与会话归属忽略                               |

查询导航失败保留当前已生效条件，展示安全恢复提示。后续写入操作的成功和冲突通过重新读取相关页反映最新状态。

## 9. 验证与验收

运行逻辑按 AGENTS.md 的完整文件口径补齐 Vitest 与 mock Playwright，逐文件行覆盖率至少 80%、分支至少 70%，零可执行分支单列适用性。实际执行项目的 npm ci、check、coverage 与 e2e，记录通过、失败、跳过和重试等真实结果。

### 单元与组件

- 全部状态省略请求 status，三个状态精确传输，q 原样、排序和分页正确。
- 关键响应结构、三个合法状态与筛选范围，Long 最大值及等价整数表示、合法 null、异常展示形态与未知字段。
- 状态／搜索／排序／页大小回第一页，URL 恢复、非法参数、深分页边界和合法空页。
- pending、错误、三类空态、同查询合并、429 清空恢复、超时与取消。
- 请求两种完成顺序、卸载、换会话、同 Token 新 revision 的保护。
- ADMIN 导航、USER 隐藏与拒绝、管理员以 USER 登录、首次管理直达与登录回跳的安全落点。
- 封面鉴权、空图与资源失败使用现有回归，并验证 DRAFT／ARCHIVED 在 ADMIN 范围的展示。

### 浏览器主流程

ADMIN 进入曲库后看到歌曲管理侧栏，进入管理列表默认全部，切换状态、搜索、排序、翻页，前进后退或刷新恢复条件。另测 USER 直接进入管理地址、登录回跳、接口 403、当前／旧会话 401 及错误重试。

管理 e2e 显式 mock 全部与单状态读取，并显式处理曲库回退请求。现有 mockApi 的默认曲库空页匹配只服务认证回归，管理用例关闭该默认分支，避免已发布筛选被自动空页替代。

视觉与交互检查覆盖 1366×768、1440×900、1920×1080、320×740、390×844 的真实导航、抽屉、列表、长内容、状态、时长、错误和分页。断言文档、内容区与表格内部的横向溢出及键盘可达性，人工查看代表截图。Chromium 结果与真实后端／其他浏览器联调分别记录。

## 10. 设计自检与书面审阅

本设计聚焦一个管理列表切片，整体导入、编辑与状态变更的已确认决定保存在任务书。接口方法、字段和状态取自现行契约，version 扩展作为后续切片的具体前置。权限、查询、空页、请求归属和恢复规则在各章节保持一致。

本次纯文档验证采用直接链接、契约、范围与一致性检查，业务构建、Vitest、Playwright 与覆盖率在代码切片执行。书面设计已获人类审阅通过，对应 [MGMT-01 实施计划](../plans/2026-11-17-track-management-list.md)进入计划审阅。
