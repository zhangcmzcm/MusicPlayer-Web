# 登录页手机一屏与浮动标签设计

日期为2026-11-06。人类已选择A「左上品牌，紧凑留白」，并确认保留小叶片装饰、桌面同步使用浮动标签。本文供书面审阅，审阅通过后编写实施计划。

## 1. 目标与任务边界

本次作为登录页的单一界面维护任务交付，覆盖手机一屏布局、各端浮动标签，以及桌面叶片变窄后的关联布局验证。

| 本轮交付 | 范围外的独立任务 |
| --- | --- |
| 手机品牌与标题间距、紧凑反馈空间、叶片容纳、未来导航容量 | 注册与找回密码业务、实际新导航、登录注册翻面 |
| 用户名、邮箱、密码、验证码的浮动标签，桌面与手机同步 | 认证API、权限、凭据存储、再次验证与全局401策略 |
| 继承人类当前尺寸调整，验证标题、文案与表单关联关系 | 依赖升级、其他业务页面与全局样式体系调整 |

上一轮布局稳定与异常恢复已获实现审核 accepted，基线为 `main / 0a30ff7`。本轮使用新的设计与实现审核计数，关联回归沿用上一轮用例。

## 3. 手机一屏布局

### 3.1 一屏验收边界

以320×740、390×844的CSS视口、默认字体、100%缩放、软键盘收起为手机一屏基线。日常输入、两行字段错误、常规接口反馈、展开的登录方式及未来两行导航容量都应完整可见，页面无横向或纵向溢出。

最长异常恢复说明、软键盘弹出、系统大字、浏览器放大或更矮窗口采用自然纵向滚动，输入、错误、焦点与操作保持可达。恢复说明继续按既有请求阶段呈现，布局随文字真实需要增长。

### 3.2 品牌、标题与反馈

- 采用A草图的左上品牌，手机品牌字号16px，图形约24×28px，沿用已有字色、字距与图形。
- 手机内容起点参考草图112px，较当前210px上移。标题组保持略向右的位置，参考偏移12px，品牌与标题之间形成约60px的可见间隔。
- 标题保留现有衬线字体与可读字号，输入及主按钮高度46px。版面通过标签布局和留白调整获得容量。
- 手机反馈区最小64px，常规反馈采用12px字号、18px行高，容纳两行原错误及一行发码通知和间隔。恢复说明加入后按实际文字高度增长。
- 手机底部参考20px留白，替换当前150px的大段留白。辅助行与底部导航继续各预留22px。
- 桌面沿用1188px叶宽与左移12%的构图，关联检查标题组和外侧竖排文案位置。浮动标签带来的字段高度变化随同验证，维持同一视口各状态的稳定布局。

以上数值是已选草图的实施起点。CSS间距及叶片几何可在已确认构图内按轮廓与容量测量微调，最终数值和截图写入功能文档。

### 3.3 叶片与装饰

- 手机白叶随紧凑表单重新确定几何，A草图参考宽950px、高1080px、顶部-220px。按实际内容检查顶部标题、底部导航与两行错误的轮廓包含。
- 主叶片几何由视口与断点控制，报错、展开方式、标签浮起各状态保持稳定。
- 保留原有三个小叶片装饰节点、背景风线、绿色渐变及其轻微运动。手机边缘小叶片保持可见，必要时调整位置以配合缩短后的场景高度。
- 小叶片与风线仍作为装饰处理，沿用aria-hidden及减少动态设置，实际位置避开文字、控件和焦点描边。
- 管理员白色／淡绿色身份叶片沿用原有风格，手机身份选择与重新登录操作纳入关联回归。

## 4. 各端浮动标签

用户名、邮箱、密码和验证码统一采用嵌入输入框上边框的标签，保持三种登录方式的布局一致。

| 字段状态 | 标签位置与样式 |
| --- | --- |
| 空值、未聚焦、无错误 | 标签在输入框内部，约13px，沿用淡灰提示色 |
| 输入框聚焦 | 标签移至上边框，缩至约11px，使用主题绿色，背景衬片覆盖标签下方边框 |
| 已有内容后失焦 | 标签保持浮起，颜色回到既有常规语义色 |
| 空值失焦且无错误 | 标签回到框内 |
| 校验错误 | 标签保持浮起，采用既有错误色，错误文案位于预留区域 |
| 禁用或请求中 | 标签按当前值保持位置，沿用禁用样式与pending约束 |
| 浏览器自动填充、刷新恢复、代码预填 | 标签与真实输入值同步，填充值和标签均清晰可读 |

浮动行为采用约150ms的位置、字号和颜色过渡，减少动态设置下直接呈现最终位置。标签定位脱离正常文档占高，浮起时字段、按钮和叶片维持原位置。

密码的已有内容判断依据实际字符串长度，处理保留首尾空格的密码。密码显示按钮、验证码发送按钮以及中文输入法行为继续可用。验证码发送按钮维持稳定宽度，倒计时文字变化时输入框宽度保持稳定。

每个字段继续具有真实可访问标签及唯一输入ID，点击标签可聚焦对应输入，错误描述和表单校验关联有效。使用当前Vue与Element Plus的表单能力完成关联，组件测试与浏览器语义定位共同验证。

## 5. 稳定空间与未来入口容量

浮动标签释放原先框外标签的占高，输入下方继续预留两行错误及其内边距。具体高度按现有12px错误字号、18px行高、6px顶部内边距验证，保持42px错误容量。

「其他登录方式」继续保留完整展开容量。收起项目沿用移出DOM的行为，展开、聚焦、切换和报错时输入及按钮的位置差值上限仍为1 CSS px。

密码辅助行和表单底部继续预留未来「忘记密码？」与「还没有账号？点这里」的空间。容量通过测试侧注入文本验证，真实入口随对应业务切片接入。验证码方式保留相同高度的辅助空间，三种方式切换时布局稳定。

手机一屏检查同时覆盖未来两行文字、展开方式和当前常规反馈。最长恢复说明的测试另行验证完整可读、自然滚动及按既有规则重新开始。

## 7. 验收与测试

- 手机基线覆盖三种登录方式、初始空值、聚焦、填值、失焦、两行校验、常规接口错误、发码通知、展开方式及未来两行导航组合。断言一屏尺寸、控件稳定与SVG轮廓包含。
- 桌面1366×768、1440×900、1920×1080覆盖相同标签状态及三种方式，沿用1188px宽度的轮廓、导航容量和安全登录回归。
- 标签行为测试覆盖空值往返、含值失焦、密码空格、校验错误、禁用、自动填充或程序预填、密码显隐及验证码倒计时。以label／输入ID和实际可访问名称验证语义。
- 键盘测试验证Tab顺序、标签点击聚焦、展开项访问、收起项移除以及中文输入法的回车保护。
- 检查三个装饰叶片和背景风线的保留、手机边缘可见性、减少动态模式及横向溢出，查看真实桌面与手机截图。
- 长恢复说明、1366×600矮窗口、真实浏览器200%缩放验证可滚动性、文本完整和键盘可达。软键盘影响通过真实手机或适当环境验证，环境缺失时在报告中记录实际完成范围。
- 实现后实际执行npm ci、npm run check、npm run test:unit:coverage、npm run test:e2e。逐个改动业务逻辑源码完整文件行覆盖率至少80%，分支至少70%，记录报告路径、失败和跳过。
