# 登录页布局稳定与异常恢复设计

日期：2026-11-05。状态：对话方案已获人类确认；本文待人类审阅，通过后编写实施计划。

## 1. 任务目标与范围

本次为已有登录切片的单一维护任务，解决错误提示及展开登录方式引起的内容增高、叶片拉伸和滚动条出现，并补充一次性凭据结果未知时的恢复提示。

范围：

- 稳定登录表单、叶片和桌面页面高度；采用人类选择的 A「预留空间」方案。
- 标题及其上下两行文字整体向右调整，保证位于白叶内。
- 为未来注册链接与忘记密码链接考虑布局容量。
- 验证码登录及管理员身份选择遇到网络错误、超时或 503 时，提供符合一次性凭据语义的恢复引导。
- 对应测试、登录功能文档与验证记录。

不包含注册／找回密码页面、真实导航入口、登录注册翻面、歌曲列表、当前用户资料、再次验证、全局 401 分流调整、依赖升级或共享样式体系重构。已有登录请求、成功响应及会话权限规则不变。

## 2. 依据与已确认决策

- 产品确认：本轮人类选择 A，普通桌面一屏；手机、矮窗口或浏览器放大时允许整页滚动。保留折叠的「其他登录方式」，不改成浮层或常驻切换栏。
- 产品确认：标题组整体向右，输入框与按钮先保持原水平位置；具体偏移以实际叶形容纳验证决定。
- 产品确认：本轮补充验证码／Ticket 的网络、超时、503 恢复提示；再次验证相关的 401 修改留给对应功能。
- [既有登录设计](2026-10-31-login-design.md)：嫩叶绿、白叶、桌面中心左移 12%、右侧竖排文案、手机居中、管理员淡绿色叶片、减少动态设置与焦点反馈。
- [主题方向](../../design/theme.md)与 `example/index.html`：配色与气质只读参考，沿用已有字体、状态色和组件惯例。
- [登录契约](../../api/auth/login.md)：验证码消费后不恢复；Ticket 一次性兑换，网络失败或 503 不能保证未消费，失效时需重新登录。初始凭据失败和 Ticket 失效分属不同错误码。
- 客户端规则：按安全错误码和请求阶段显示反馈；卸载／主动取消静默；不根据后端 detail 分支，不记录凭据，不自动重复登录。

## 3. 现状与根因

`AuthScene.vue` 的 scene-main 具有至少 920px 高度，手机至少 880px；scene-content 使用较大的上下 padding 并由内容决定最终高度。主叶片高度取场景高度，因此内容变化能同时改变场景和叶片尺寸。

全局字段错误使用静态定位，新增错误行会进入正常文档流；LoginForm 的其他方式通过条件渲染展开，同样增加高度。LoginView 的接口错误和验证码通知也会新增占高。这些变化叠加后，可能跨过视口高度阈值，使滚动条出现并引起可视区域变化。仅添加过渡或隐藏页面溢出无法解决内容容量问题。

本轮在认证场景及登录组件内处理所需布局，避免为修复登录而改变未来其他业务表单的全局规则。

## 4. 稳定布局方案

### 4.1 视口、叶片和内容的关系

- 常规桌面验收基线为 1366×768、1440×900、1920×1080 的 CSS 视口，默认字体与 100% 缩放下，一屏容纳登录及其可展开状态，无横向或纵向页面溢出。
- 叶片与布局容量由视口及响应式断点决定，不根据错误显示、选项展开或表单内容实时计算高度；不因这些状态缩放或拉长叶片。
- 桌面叶片保持已确认的中心左移 12% 构图；输入及按钮水平对齐关系保留。允许调整场景上下间距与叶片实际尺寸以满足容量，不机械保留原先 920px 最小高度和大 padding。
- 手机、桌面矮窗口、较窄窗口及放大后的空间不足状态，采用可整页滚动的布局。不能以缩小字号、裁切错误信息、禁用页面滚动或在叶片内部创建滚动区来强行塞入一屏。
- 页面装饰与业务内容分层；保证焦点描边不被裁切，无横向滚动。滚动条若确有必要，应来自可访问的内容长度，而不是装饰或状态切换产生的意外溢出。

### 4.2 表单区域预留

保留以下稳定区域：标题组、反馈区、两组字段、提交按钮、登录方式区、未来导航容量。

- 每个字段预留可显示两行当前校验文案的错误区域，校验出现／消失不推动下一个字段、忘记密码容量或提交按钮。允许文案换行，不省略、截断或只依赖悬浮提示。
- 请求反馈区预留容纳本轮最长恢复文案的高度；验证码发码成功通知与接口错误按当前实际状态呈现，布局同时覆盖可能并存的反馈，不能依靠覆盖或隐藏通知节省空间。
- 其他登录方式区按两个备选方式实际展开占用的最大高度预留。收起时保留自然留白；展开只改变内容可见性，提交按钮、底部和叶片不移动。
- 收起的选择项不得获得焦点或被辅助技术当作可操作项；展开后正常键盘访问，切换方式仍清除原敏感输入和校验反馈。
- 本轮对未来两种导航文字仅预留布局容量，不渲染无效链接、禁用占位按钮或「敬请期待」。注册文案可占底部一行，忘记密码文案可占密码字段下方靠右一行。未来上线时按对应切片验证实际文案与窄屏换行。
- 极端字体放大导致超过预留容量时，内容允许自然增长并通过整页滚动访问；不承诺所有字号与视口都固定高度，也不压缩文字来保持一屏。

### 4.3 标题与动效

- 上方英文、主标题「听见，风的声音」、下方说明作为同一组，向右做小幅调整；不改变三者内部对齐关系，不联动平移输入框和按钮。
- 偏移由 CSS 实现，在各断点按叶片轮廓检查；手机空间不足时减少偏移，保持三行完整。既有管理员身份选择标题保持其居中语义，不机械套用登录标题偏移。
- 不新增叶片尺寸动画掩盖布局跳动。允许已有色彩和透明度过渡；减少动态设置下无额外空间运动。

## 5. 一次性凭据异常恢复

### 5.1 分类和显示规则

新增提示按当前请求阶段和归一化错误分类产生。属于操作上下文补充说明，不覆盖原错误对象，不发明后端错误码，也不将「可能已消费」表述为确定事实。

| 请求阶段与错误 | 显示及状态行为 | 恢复操作 |
| --- | --- | --- |
| 管理员身份兑换：NETWORK_ERROR、TIMEOUT 或 HTTP 503 | 显示安全错误及「本次身份选择可能未完成，登录凭据也可能已失效，请重新登录后选择。」；保留身份选择状态，不假成功、不自动清除有效 Ticket | 保留并突出可见的重新登录操作，调用现有 restart，清理 Ticket 与密码／验证码后返回登录表单 |
| 验证码登录提交：NETWORK_ERROR、TIMEOUT 或 HTTP 503 | 显示安全错误及「本次登录结果未确认，验证码可能已被使用，请在允许发送后重新获取验证码。」；保留邮箱、当前方式及原有限流截止时间 | 使用现有发码入口，冷却未结束时继续禁用；不自动发码，不自行重置额度 |
| 用户名／邮箱密码登录：同类错误 | 保持现有网络、超时、服务不可用提示，不额外宣称密码等凭据已消费 | 用户自主再次提交，沿用防重复与限流 |
| 发送登录验证码失败 | 沿用当前发码错误和 scope／Retry-After 行为，不混用「提交的验证码已消费」提示 | 用户在允许时重新申请 |
| INVALID_CREDENTIALS | 沿用凭据错误提示，不把明确拒绝冒充结果未知 | 留在登录方式内修改输入或自主重新发码 |
| LOGIN_TICKET_INVALID | 沿用清除 Ticket 与要求重新登录的行为 | 返回登录流程 |
| ROLE_SELECTION_NOT_ALLOWED、429、校验／存储／客户端错误 | 保留各自原错误语义，不附加本轮结果未知说明 | 按原流程恢复，无权限不提升身份，限流继续计时 |
| CANCELLED、卸载／过期请求 | 不显示结果未知说明，不更新已退出页面 | 不自动重试或恢复旧状态 |

### 5.2 生命周期与数据流

- useLogin 负责把本次操作上下文与归一化错误转为用户反馈，反馈状态仅属当前登录页面，不写入共享会话或存储。
- LoginView 负责显示错误与恢复提示；LoginForm、RoleSelection 继续通过 props／emit 展示和触发动作。
- auth store 继续负责会话、票据、并发代数与 pending，不因文案修改改变身份、Ticket 有效期或 Token 存储方式。
- 新操作开始、切换登录方式、重新开始或成功时清理过期的恢复提示；收到过期响应不能覆盖新操作反馈。
- 不改变 API 请求／成功响应守卫及统一 HTTP 401 策略，不将503或网络失败伪造为登录成功。

## 7. 验收与测试

### 7.1 布局及交互验收

- 桌面基线分别检查三种登录方式的初始、字段错误、接口错误、发码成功、折叠／展开及错误与展开组合。比较叶片、两组输入、提交按钮的边界；相同视口下状态切换无高度／位置跳变，允许计算及像素舍入造成的 1 CSS px 差值。
- 标题组、字段、按钮及实际错误文案均在白叶可用轮廓内；标题整体偏移不会让右边文字越界。沿用现有 SVG 坐标轮廓检查并查看实际截图。
- 手机至少覆盖 320×740、390×844；矮窗口覆盖 1366×600。允许纵向整页滚动，全部内容与按钮可访问，无横向溢出、无内部滚动或遮挡。
- 人工检查浏览器 200% 缩放下的自然重排、文字完整与可滚动性；不把单纯改变 deviceScaleFactor 当作浏览器缩放验收。
- 使用测试专属的导航文案容量探针验证未来两行容量，不能把假链接放入产品路由／模板。探针只用于布局测试，不声称注册与找回业务已实现。
- 展开状态 aria-expanded 正确，收起项目不可聚焦，键盘和减少动态模式可操作；保留管理员普通／管理两种身份与手机展示回归。

### 7.2 异常恢复测试

- NETWORK_ERROR、TIMEOUT、503 分别覆盖验证码登录与 Ticket 兑换，断言恢复提示、状态保留、请求仅发一次、无自动重试或发码。
- 验证重新登录动作清理 Ticket 和敏感输入；冷却中的发码继续禁用，允许发送后能正常发码。
- 密码登录、发码错误、INVALID_CREDENTIALS、LOGIN_TICKET_INVALID、403、429、取消、卸载及迟到响应保留原语义，不出现错误阶段的恢复提示。
- 新操作、切换方式、重新开始与成功清理旧提示；已有三种登录、null 邮箱管理员、会话恢复、安全回跳和 401 回归保留。

### 7.3 验证与报告

实现后实际执行 `npm ci`、`npm run check`、`npm run test:unit:coverage`、`npm run test:e2e`，记录失败、跳过及人工视觉检查结果。逐个改动业务逻辑源码的完整文件行覆盖率至少 80%、分支至少 70%；纯样式部分说明验证依据，不写与实现重复的无意义测试。

按现行审核模板提交本轮变更及关联回归；这是新维护任务，不重开已 accepted 的旧登录审核。未确认的未来业务不纳入本轮通过条件。

## 8. 设计自检

- 方案复用既有主题与权限决策，仅改变已确认的布局关系和结果未知提示。
- 桌面一屏与极端视口可滚动具有明确适用边界，没有用隐藏溢出承诺所有设备一屏。
- 预留两行错误、长恢复提示和未来导航分别考虑，不能以同一块空间互相覆盖。
- 未来入口只验证容量，不制造假链接；一次性凭据失败不被断言为确定已消费。
- 工作区已有 API 文档与任务书不纳入本次设计文档提交，后续按人类指定范围处理。
