# 登录页设计方案

日期：2026-10-31。

状态：交互与视觉方向已经逐项确认；本书面方案提交人类审阅，审阅通过后编写实施计划。

## 1. 目标与切片边界

交付一个可独立验收的登录流程，支持邮箱密码、用户名密码、邮箱验证码，以及管理员认证后的本次登录身份选择。由于仓库当前只有文档与视觉样例，本切片包含运行和验证登录流程必需的前端脚手架。

本次包含：

- `/login` 页面、三种登录方式、登录验证码发送、管理员身份选择和成功状态。
- 会话存储、统一 HTTP 封装、错误映射、认证与角色守卫所需的基础能力。
- Vue 工程、单元与组件测试、网络 mock 的端到端测试、功能文档。
- 与登录直接相关的嫩叶绿视觉和管理员身份选择动效。

本次不包含：注册业务、找回密码业务、歌曲列表、上传、收藏、播放列表、播放历史及管理端业务页面。不创建这些功能的空路由、假入口或假数据。默认落点的产品方向为歌曲列表，随该独立切片接入。

登录与注册之间的翻面动效已通过独立样片确认，作为未来注册接入时的共同设计。本切片不为了展示该动画而增加不可用的注册按钮。样片中的注册字段只用于构图研究，不构成注册业务契约。

## 2. 设计依据与已确认决策

- 主题规范只读引用 `docs/design/theme.md`，视觉参考只读引用 `example/index.html`，不修改上述文件或 `example/` 内容。
- 沿用嫩叶绿配色、白叶轮廓、外围叶脉、系统衬线标题和系统无衬线表单文字。
- 白叶比原样例更饱满；初始比较中选择 B 的约 125% 视觉尺度。最终叶片尺寸以真实表单及校验提示的容纳空间为准，不固定放大倍数。
- 桌面最终采用左右各偏移 12% 的落点，取代之前试验中的 8% 和 18%。偏移以叶片整体几何中心相对视口中线计算，避免用 SVG 容器边界代替实际叶形中心。
- 登录叶片在左，叶脉右倾；未来注册叶片在右，翻面后叶脉左倾，叶尖仍朝上。
- 桌面外侧空白放置两列竖排中文，登录在右、注册在左。手机隐藏这组装饰文案。
- 手机白叶和表单居中，取消左右偏移；未来切换保留小幅飘移与翻面。矮屏允许纵向滚动，不靠缩小文字压入一屏。
- Token 和会话使用 `sessionStorage`；管理员身份选择票据仅保存在内存。
- Element Plus 全量引入，原生 CSS，组件使用 `<style scoped>`；不引入新样式体系。
- 中文文案，不引入 i18n；面向现代 Chrome、Edge、Firefox、Safari 及手机浏览器，不兼容 IE。
- 覆盖率沿用新增或修改源码行覆盖率至少 80%、分支覆盖率至少 70%。

## 3. 页面布局与视觉

### 3.1 桌面登录姿态

左上角保留“风与叶”品牌。背景由嫩叶绿受光与阴影区域、疏朗白色风线、少量低透明度小叶片构成，不增加矩形表单卡片。背景微动沿用主题的缓慢节奏，主叶片和表单在等待输入时保持稳定。

表单在白叶内部垂直居中略偏下，桌面以约 340px 宽为构图起点。内容依次为轻量英文眉题、“听见，风的声音”标题、辅助文案、当前方式的字段、主按钮、“其他登录方式”。叶脉不穿过文本；输入边界与按钮形状沿用主题样例的细边框、12px 输入框圆角和胶囊按钮。

叶片须容纳真实表单、字段校验提示、接口错误和成功状态。允许按内容增加叶片大小或页面高度，不裁切提示，不使表单溢出白色区域。不能将页面直接画成一整张 SVG：业务表单使用可访问的 HTML 和 Element Plus 组件，SVG 只用于装饰。

外侧竖排主文案使用“一叶清新，一曲自在。”，分为“一叶清新”“一曲自在”两列，按传统竖排顺序从右列读向左列。装饰排版不显示逗号与句号。位置参照人类提供的截图红框：位于叶片靠视口中线方向的轮廓外，在另一侧留白内垂直居中。文案不沿叶片曲线弯排，不填满整块空白，不加底色或边框，不使用镜像文字。以柔和深绿色、系统衬线字体和舒展字距呈现，视觉分量低于表单标题。

桌面宽度不足以同时容纳叶片、表单和外侧文案时，优先隐藏装饰文案并转为居中布局；断点根据真实内容是否碰撞确定。手机至少检查 320px 宽以及常见横竖屏，不出现横向滚动。

### 3.2 状态样式

- 悬停：按钮绿色略加深；可操作小字链接加下划线。
- 键盘聚焦：输入、按钮及登录方式选项显示清晰绿色外描边。
- 禁用和加载：降低饱和度并保留文字可读性；主操作显示加载图标。
- 校验错误：低饱和暗红色边界，字段下方给出文字提示，不只依靠颜色。
- 普通状态变化约 150ms，不增加缩放、弹跳或玻璃装饰。
- 表单输入支持明确标签、自动填充、键盘提交和可访问的错误关联。装饰 SVG 与重复装饰文案不参与键盘导航。

这些语义状态方案已获人类确认；具体 CSS 值应保持上述语义和可读性，不改变主题方向。

## 4. 登录方式与表单行为

### 4.1 默认与切换

默认邮箱密码登录。主按钮下方以小字“其他登录方式”作为展开入口，展开后只列另外两种登录方式，选中后收起。入口应使用按钮语义，并提供展开状态，不采用没有交互语义的文本。

邮箱在邮箱密码与邮箱验证码之间保留。切换时清空密码、验证码、旧校验与接口错误；用户名字段与邮箱字段分别维护，不能相互误用。切换不触发登录请求。与邮箱发送冷却相关的状态不能通过切换登录方式重置。

### 4.2 输入与校验

- 邮箱：必填、合法邮箱、最多 120 字符；发送验证码与邮箱登录采用一致的去首尾空白和小写规范化。
- 用户名：必填，3–80 字符；不自行发明额外字符规则或改写用户名大小写。
- 密码：必填，8–128 字符；不裁剪空格，不自行增加复杂度规则。支持显示与隐藏、粘贴和浏览器自动填充。
- 验证码：必填，6 位数字；使用字符串保存，保留开头的零。
- 表单采用 Element Plus rules；提交前校验，失败不发出请求。允许 Enter 提交，避免输入法组合过程中误提交。

邮箱验证码行包含验证码输入与发送按钮。发送前只校验邮箱；发送成功显示 60 秒重发倒计时，验证码有效期依据响应的 UTC `expiresAt`。冷却状态按邮箱和登录用途关联，切换表单不能绕过对同一邮箱的冷却；后端仍是限流最终依据。

### 4.3 请求与反馈

提交期间禁用提交、发送验证码和登录方式切换。验证码发送期间也防止重复发送及与登录请求交错。各请求以独立 pending 状态表达，完成后恢复可操作性。

字段校验在输入框下方展示。认证失败不区分账号不存在、密码错误或验证码错误，统一安全提示。接口失败不得直接展示原始后端 message、堆栈或内部路径。

注册和忘记密码的未来位置提前确定：注册在表单底部，忘记密码在密码框下方靠右且只出现在密码登录方式。当前正式页面不渲染这两个不可用入口；对应页面可用后，由其切片接入。

## 5. 管理员身份选择

收到 `ROLE_SELECTION_REQUIRED` 后，不保存登录会话，也不从用户输入推断管理员权限。内存保存返回的 `loginTicket` 与 `expiresAt`，进入身份选择步骤。

登录表单淡出，原大白叶随风退到背景并淡去。风带来两片较小的叶子：白色“用户身份”和淡绿色“管理员身份”，分别附简短用途说明。使用明确的身份文字区分，颜色不作为唯一标识。桌面并排，手机上下排列；叶形围绕真实文字与按钮调整，不采用两个矩形大卡片。

两片叶子到位后保持稳定并启用选择。悬停仅轻微加深阴影；键盘焦点清晰。选择区采用原生按钮语义；动画期间的暂时禁用有明确状态，开启减少动态效果时直接进入可选状态。两项不必等装饰性背景动画结束才可操作。

点击任意身份后，以同一登录接口发送 `ROLE_SELECTION`、票据和对应 `loginRole`。该项显示加载，两项同时禁用。只在服务器返回 `AUTHENTICATED` 后建立会话，以响应中的本次身份为准。

票据本地到期或后端返回 `LOGIN_TICKET_INVALID` 时，清空票据并返回登录表单，提示“身份选择已过期，请重新登录”。不在计时器、日志或 URL 中暴露票据。刷新页面时不恢复票据，显示初始登录表单。

`ROLE_SELECTION_NOT_ALLOWED` 给出无权限提示，不建立会话。网络或服务异常显示可恢复错误，不自动重放一次性票据；提供重新登录的路径，重试能否成功仍以后端票据状态为准，不能假定失败请求未消费票据。

## 6. 登录与未来注册之间的翻面

已比较过平面旋转 180°、两个独立页面分别淡出淡入，以及共享场景翻面。最终确认共享场景翻面：同一片叶子保持叶尖朝上，从右倾翻为左倾。

登录和未来注册采用两个路由，共享持续存在的场景外壳。场景负责背景、叶片、阴影和运动，路由页面分别负责业务表单，避免把两套业务挤进一个组件，也避免页面切换时背景闪动和叶片重建。

动效以已获确认的独立样片为依据：

1. 风线先增强，表单和外侧装饰文案淡出。
2. 叶片随后响应，向另一侧小幅抬起并飘移，沿斜向翻面。
3. 侧身时产生轻微卷曲和阴影变化，不缩成机械直线，不采用平板卡片匀速翻转。
4. 接近另一落点时减速，极轻回摆后稳定；新表单和另一侧竖排文字淡入。

样片完整节奏约 2.6 秒，作为当前设计参考；正式接入要兼顾可操作性，不额外延长。背景微动与转场不重复叠加造成持续晃动。表单文字不随叶片旋转、镜像或压扁。

落点最终使用左右各 12%，叶片大小根据表单调整。手机不保留桌面左右落点，仅居中小幅飘移翻面。`prefers-reduced-motion` 下停用背景循环和空间运动，用短淡入淡出或直接呈现最终状态，不阻挡页面访问。

直接打开未来注册地址时显示其稳定姿态，不强制播放登录转场；浏览器返回可反向过渡。转场期间避免重复触发，导航取消、页面卸载或减少动态设置变化时应能清理动画并恢复一致的最终状态。

可视化样片保存于被 Git 忽略的 `.superpowers/brainstorm/`，不作为构建资源或交付依赖。正式实现应将必要的原创 SVG 与场景行为纳入源码，而非引用该本地目录。

## 7. API 契约与数据流

依赖的人类维护契约：

| 操作 | Method + Path | 文档 |
| --- | --- | --- |
| 三种登录及管理员身份选择 | `POST /api/v1/auth/login` | `docs/api/auth/login.md` |
| 发送登录验证码 | `POST /api/v1/email/send-code` | `docs/api/email/send-code.md` |

按当前方式发送契约中必要字段，不发明字段，也不混发其他登录方式的密码、验证码或票据。发送验证码固定使用 `purpose: LOGIN`。认证请求不附加过期的 Bearer Token，也不经过受保护请求的登录回跳逻辑。

数据流为：表单校验 → 认证动作 → `src/api/` → HTTP 错误转换或契约响应 → 更新页面步骤或保存会话。组件与 store 均不能直接 import axios；单实例负责 baseURL、超时、Token 注入及响应错误转换。

`VITE_API_BASE_URL` 提供 API 基址；统一 `/api/v1` 前缀只拼接一次。开发服务器将 `/api` 代理到由环境变量提供的后端目标，业务源码不硬编码后端域名。配置 `.env.example` 仅包含占位配置，真实本地环境文件维持忽略。

## 8. 会话、安全与导航

`AUTHENTICATED` 后，Pinia 统一保存 `accessToken`、`tokenType`、`expiresAt` 及响应会话用户信息，写入 `sessionStorage`。刷新同标签页后恢复，已到期、损坏或结构不合法的数据清除。密码、验证码和身份票据不写入持久存储；不增加刷新 Token 或自动续签逻辑。

`sessionStorage` 对页面脚本可见，人类已选择该存储方式；不将其解释为后端授权依据或跨标签页长期登录。前端角色取自认证响应，最终权限以后端为准，不从 URL、表单、装饰文字或身份按钮推断已获得权限。

已有会话的受保护请求返回 401 时统一清除会话并跳转 `/login`，携带安全的站内回跳地址；不无限重试。登录接口的 `INVALID_CREDENTIALS` 留在表单，身份票据 401 则回到登录步骤，不能套用受保护请求的 401 跳转。

当前没有业务落点时，登录完成在登录页显示真实“登录成功”和本次身份，清理敏感表单数据与票据。不增加空歌曲列表路由。后续歌曲列表接入后作为默认落点；受保护页面发起登录时优先返回有效的站内目标，拒绝外部地址、协议相对地址、登录自循环和不存在的目标。

路由懒加载，守卫仅控制认证与角色导航。增加必要的 404 兜底，不为测试角色守卫增加虚假业务页面；可在隔离测试路由表中验证守卫。

## 9. 错误处理

HTTP 统一转换为包含 `code`、`status`、安全错误信息及限流信息的业务错误，用户文案集中映射。行为分支依据稳定 code 与 HTTP 状态，不根据后端 message 文本。

| 情况 | 页面行为 |
| --- | --- |
| 本地校验失败 | 字段下方提示，阻断请求 |
| `VALIDATION_FAILED` | 安全的输入校验提示，保留可修正输入 |
| `INVALID_CREDENTIALS` | 留在当前登录表单，统一认证失败提示 |
| `LOGIN_TICKET_INVALID` | 清空票据，返回登录步骤 |
| `ROLE_SELECTION_NOT_ALLOWED` / 其他 403 | 无权限提示，不建立会话，不泄漏数据 |
| `LOGIN_RATE_LIMITED` | 显示限流提示，按 `Retry-After` 暂停登录按钮并显示剩余时间 |
| `SEND_CODE_TOO_FREQUENTLY` | 显示发送限流提示，按 `Retry-After` 禁用发送；可依据契约 scope 区分邮箱冷却、每日上限与 IP 限流 |
| `EMAIL_SEND_FAILED` | 提示邮件发送失败，允许用户按状态重新操作 |
| 状态存储不可用、验证码存储不可用、500/503 | 安全的暂时不可用提示，不假成功、不自动重试 |
| 超时、断网 | 分别提供可理解的网络反馈，恢复可操作状态 |
| 公共层收到 404、409、未知 429 或其他 5xx | 分别映射资源不存在、冲突、限流、服务异常；不发明登录特有业务含义 |
| 未收录 code 或非法响应 | 通用安全提示并经统一脱敏日志记录，不把原始响应显示给用户 |

倒计时基于截止时刻计算，不仅每秒减一，避免后台标签页计时漂移。无有效 `Retry-After` 时不猜测服务端解封时刻，展示限流错误并保留防重复提交。邮箱发送成功的本地 60 秒冷却与服务端限流同时存在时，不提前解除服务端限制。

组件卸载、切换步骤和会话变化时，清理计时器、取消请求或忽略过期结果。旧请求不能覆盖新页面、恢复已失效票据或写回旧会话。不吞异常、不记录 Token、密码、验证码、票据或邮箱原始请求体。

## 10. 工程与组件边界

沿用 Vue 3 Composition API、`<script setup>`、纯 JavaScript、Vite、npm、Vue Router、Pinia、Axios、Element Plus、Vitest 与 Playwright。禁止引入 TypeScript。Node 使用仍受支持的 LTS 版本，并在实施计划中结合依赖要求锁定到 `.nvmrc` 和 `engines`；不把当前机器安装版本直接当作项目版本决策。

预计职责划分：

- `views/login/`：登录路由页面，编排登录、身份选择、成功步骤，不实现注册业务。
- `components/auth/`：可复用场景、受控表单展示、身份叶片展示；通过 props/emit 交互，不自行获取业务数据。
- `composables/`：表单步骤、验证码冷却及页面私有的异步交互；清理请求和计时器。
- `stores/auth.js`：setup store，会话、身份票据及认证动作，显式 pending/error。
- `api/`：单一 Axios 实例、认证与邮件 API。
- `utils/`：错误映射、会话序列化和安全回跳等纯逻辑。
- `router/`：懒加载路由、导航守卫与 404。

全局 CSS 仅包含必要重置、主题变量和 Element Plus 主题覆盖，组件布局与叶片样式保持 scoped。Element Plus 使用全量引入，后续业务切片不更换方式。新增依赖只用于规定技术栈及必要测试、格式检查工具，不为叶片动画引入重量级动画库。

基础脚本包含 `dev`、`build`、`preview`、`lint`、`lint:fix`、`format`、`format:check`、`test:unit`、`test:unit:watch`、`test:unit:coverage`、`test:e2e`、`check`，与项目协议一致。Playwright 固定 webServer 运行方式，HTTP 全部 mock。

## 11. 测试与验收

Vitest 覆盖用户可见行为与关键状态：

- 三种登录请求的正确字段、默认方式、方式展开与切换、邮箱保留、密码及验证码清除。
- 邮箱、用户名、密码和验证码的空值、长度与格式边界；密码不 trim，验证码保留前导零。
- 密码显示与隐藏、键盘提交、加载禁用与防重复提交。
- 验证码发送成功、冷却、换方式或换邮箱、429 scope 与 Retry-After、超时及邮件失败。
- 普通用户成功、管理员身份选择、两种身份请求、票据过期与失效、403、网络失败。
- 登录凭据 401 与已有会话失效 401 的区别，会话恢复、到期、损坏存储和安全回跳。
- 404、409、429、5xx、未知错误和脱敏兜底；过期响应、取消请求与卸载清理。
- 场景最终姿态、减少动态效果、转场清理与键盘操作；不以动画内部每一帧的数值代替用户行为断言。

Playwright 使用稳定 `data-testid`，默认通过 `page.route` mock 至少验证：邮箱密码登录、用户名密码登录、验证码发送与登录、管理员选择用户身份、管理员选择管理员身份。补充认证失败恢复、限流与禁止重复提交、刷新会话恢复、手机布局和减少动态效果的关键流程。

视觉验收检查桌面 12% 落点、外侧两列竖排文案、手机居中与装饰隐藏、真实字段错误下的叶片容纳、身份叶片的白色与淡绿色区分、焦点可见，以及无横向滚动。正式页面实际截图检查，不以“服务能打开”代替视觉验证。当前独立样片只能证明方向，不代替 Vue 实现验收。

实现完成后实际执行 `npm ci`、`npm run check`、`npm run test:unit:coverage`、`npm run test:e2e`。需要时安装 Chromium；环境缺失导致未运行必须如实报告，不能记为通过。覆盖率按本次新增或修改源码计算，测试、产物和依赖不计入源码阈值。
