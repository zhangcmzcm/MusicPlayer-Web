# 注册页与共享树叶翻面设计

日期为 2026-11-07。本文记录人类在本次对话逐节确认的设计，供书面审阅。书面审阅通过后进入实施计划。

## 1. 目标与边界

本次为 AUTH-01 注册功能切片，交付可选邮箱的用户名注册、登录与注册双向导航，以及共享场景的树叶翻面。手机登录页同步调整顶部布局，保证两个页面衔接一致。

交付内容包括 `/register`、注册表单、注册及 REGISTER 邮箱发码调用、注册成功回登录预填、共享树叶转场、必要的安全回跳调整、测试与功能文档。沿用现有 `/login` 三种登录方式和管理员身份选择。

范围外包括找回密码业务、账户资料、邮箱变更、再次验证、歌曲列表、全局 401 策略重构、依赖升级、主题体系重构。找回密码入口随完整找回流程接入。

本次文档提交仅包含本文。实现代码与功能文档在后续实施切片交付。

## 2. 依据与决策复用

- 注册契约见[注册用户](../../api/auth/register-user.md)，公开 `POST /api/v1/auth/register`，成功状态为 201，创建角色固定为 USER。
- 发码契约见[发送邮箱验证码](../../api/email/send-code.md)，公开 `POST /api/v1/email/send-code`，本流程用途固定为 REGISTER。
- 任务来源为[登录后续任务书 AUTH-01](../../tasks/login-follow-up.md)。
- 共享场景、桌面左右各偏移 12%、叶尖朝上的翻面节奏、外侧竖排与减少动态沿用[登录设计第 2、6 节](2026-10-31-login-design.md)。
- 浮动标签、装饰叶片、错误描述关联与容量验证沿用[手机一屏与浮动标签设计](2026-11-06-login-mobile-floating-labels-design.md)及[登录功能文档](../../features/login.md)。本次人类确认的手机顶部同行布局取代原手机独立标题组布局。
- 配色与视觉气质引用[主题规范](../../design/theme.md)和[视觉样例](../../../example/index.html)。这些人类维护文件只读引用。

此前比较的邮箱注册主流程、双方式切换，本次确定为单一表单，邮箱选填。成功行为在自动回登录与停留成功状态之间选择前者。密码确认选择独立确认密码框。

## 3. 表单与请求

### 3.1 字段顺序与校验

用户名、密码、确认密码、邮箱始终显示。用户名、密码、确认密码标 `*`，邮箱标注“选填”。邮箱有内容时展开验证码及发送按钮，验证码标 `*`。浮动标签在桌面和手机一致，沿用真实标签、唯一输入 ID、错误描述关联与键盘可操作性。

| 字段 | 规则与客户端行为 | 依据 |
| --- | --- | --- |
| username | 3–20 位 ASCII 英文字母、数字或下划线 | 注册契约请求字段 |
| password | 8–72 个 U+0020–U+007E 字符，禁止全空格。保留首尾空格，原样提交 | 注册契约请求字段与密码说明 |
| confirmPassword | 与 password 完全一致，仅本地校验，提交体省略该字段 | 人类本次选择 B |
| email | 空字符串表示未填写；有内容时校验邮箱格式及最多 120 字符，空白内容不能绕过邮箱校验 | 注册与发码契约 |
| code | 有邮箱时必须为 6 位数字字符串，保留前导零；无邮箱时省略 | 注册契约条件必填 |

两个密码框各有可通过键盘操作的显示／隐藏按钮。密码修改后，已触发的确认密码校验须同步更新。注册密码规则局限于注册，已有登录密码仍沿用登录契约。

无邮箱时仅发送 username、password。有邮箱时增加 email、code。清空或修改邮箱时清除验证码及旧邮箱相关的成功提示，避免误用。修改后的迟到发码响应不能覆盖当前邮箱状态。

邮箱为空时显示轻量说明“未绑定邮箱的账号暂不支持自助找回密码”。绑定邮箱的说明使用“可用于邮箱登录，后续找回密码也将使用该邮箱”，体现找回功能的当前进度。

### 3.2 发码与防重复

发送前仅校验本次需要的邮箱字段，以 REGISTER 用途调用既有公开接口。成功展示发送通知并启动同一邮箱、同一用途的 60 秒冷却。验证码有效期为 300 秒，以响应 expiresAt 表达，不从邮件到达时间重新计算。

沿用现有 Retry-After 安全解析与 scope 呈现规则，分别处理邮箱冷却、邮箱日限额及 IP 限流。邮箱变更不能清除仍适用的 IP 限流，也不能绕过已知的原邮箱冷却。LOGIN 与 REGISTER 的邮箱用途限额分别处理。

发码期间防止重复发送，注册提交期间防止重复提交以及表单编辑引起的提交上下文漂移。界面使用可见加载和禁用状态。操作结束恢复可操作状态，失败由用户决定下一步。

发码失败、超时或网络中断不自动重发，不将“请求失败”等同于“邮件一定未发出”。发送失败按稳定错误码展示安全反馈，不展示后端原始 detail 或 message。

### 3.3 成功响应的消费

201 注册成功后转入回登录流程。该响应只用于确认注册完成，不构造登录会话，不从其 userRole 赋予客户端权限。已有会话存储机制保持原协议。

登录预填采用本次已提交的用户名，通过内存传递。响应 id、email、userRole、createdAt 不参与本次导航或授权，不对这些未消费的展示字段添加认证级拒绝条件。忽略无关新增字段，避免成功创建账户后因无关响应字段误报注册失败。

## 4. 页面构图与容量

### 4.1 桌面

登录白叶在左，注册白叶在右，整体几何中心相对屏幕中线各偏移 12%。注册侧叶脉左倾、叶尖朝上，外侧左方显示两列竖排文案。沿用嫩叶绿渐变、白叶、外围叶脉与轻微阴影。

注册标题为“让喜欢，就此启程”，副文案为“从一片叶，遇见你的旋律。”。登录桌面标题组继续沿用当前布局。

叶片尺寸按完整注册表单及错误容量确定，由视口与页面类型控制。输入、报错或验证码展开不驱动白叶突然伸缩。保留背景风线与三个小叶片装饰，装饰避开文字、输入和焦点描边。

### 4.2 手机

手机登录与注册统一采用顶部同行布局，“风与叶”在左，页面主标题在右。品牌固定，主标题随页面切换。适当调整字号与字距保证 320px 宽视口可读，手机隐藏标题上下的英文与副文案。桌面标题组继续独立呈现。

表单居中，缩小字段间距。输入及按钮沿用现有可操作尺寸，错误区保留紧凑的两行容量。错误文本按真实需要排版，禁止裁切反馈或以过小字号换取高度。

验证码区域平滑展开、收起，白叶保持稳定。容量按完整状态设计，日常注册按钮及“已有账号？去登录”都纳入测量。邮箱隐藏状态可减少实际表单占高，展开后的布局须满足同样的可达性要求。

一屏基线沿用 320×740、390×844 CSS 视口、默认字体、100% 缩放、软键盘收起。检查完整五字段、两行字段错误、两行常规接口反馈与一行发码通知并存，以及底部导航容量。登录的其他登录方式展开、现有导航容量和三种方式同时回归。

极矮视口、软键盘展开、放大字号及较长结果未知说明采用自然纵向滚动，保证字段、错误和按钮可达。布局不产生横向溢出。实现时先调整允许的间距和叶片几何，若基线确实无法容纳，应提交测量结果由人类裁定容量边界。

## 5. 双向导航与树叶动画

### 5.1 路由与信息传递

`/login` 与 `/register` 作为同一持续存在的 AuthScene 下的两个子路由，分别负责各自业务表单。链接使用真实 RouterLink，支持直接打开地址与浏览器前进后退。

登录表单底部显示“还没有账号？去注册”，注册底部显示“已有账号？去登录”。普通切换清除密码、确认密码和验证码，页面重新进入时使用其默认表单状态。

注册成功后清除敏感输入，自动反向翻面到 `/login`，切换到用户名密码登录，预填本次注册用户名，密码留空，显示注册成功提示。内存中的一次性成功交接信息被消费后清除，不写入 URL、本地存储或日志。刷新后按正常登录页呈现。

从登录带来的安全站内 redirect 随导航保留，注册成功回登录后，完成登录再前往目标。扩展现有 resolveSafeRedirect，使 login、register 以及认证入口重定向均不能成为登录后的回跳目标，防止认证路由循环，保留现有外站、编码、反斜线等拒绝规则。

### 5.2 动效节奏

1. 风线先增强，当前表单和外侧文案淡出。
2. 白叶轻抬并向另一侧飘移，沿斜向翻面。
3. 侧身时通过轻微卷曲与阴影变化保持叶片质感。
4. 接近落点时减速，极轻回摆后稳定，新表单与文案淡入。

叶尖始终朝上。表单文字独立于叶片变换，始终正向可读。完整节奏参考已确认样片约 2.6 秒，正式实现不额外延长等待；可操作区域在清晰可见后恢复交互。手机维持居中，以小幅飘移完成翻面。

直接打开任一路由时呈现对应稳定姿态。前进、后退可反向转场。转场内防止重复触发，导航取消、快速历史导航、离开认证场景或减少动态设置变化时清理动画，以最终路由为姿态依据。

减少动态模式停用背景循环及空间运动，采用短淡入淡出或直接呈现。切换完成后聚焦目标页标题，成功回登录后播报成功提示。离场表单在过渡期间不能残留可交互焦点。

## 6. 错误与生命周期

| 情况 | 界面与恢复行为 |
| --- | --- |
| 本地校验失败 | 对应字段显示错误，定位首个错误，不发送注册请求 |
| USERNAME_ALREADY_EXISTS / EMAIL_ALREADY_EXISTS | 明确提示对应字段冲突，保留其他输入供修改 |
| USER_ALREADY_EXISTS | 提示账户信息冲突，不能推断具体冲突字段 |
| EMAIL_CODE_INVALID / EMAIL_CODE_ALREADY_USED | 提示验证码无效或已使用，引导在允许发送时重新获取 |
| EMAIL_CODE_ATTEMPTS_EXCEEDED | 提示尝试次数达到限制，引导重新获取，遵守返回的限流信息 |
| VALIDATION_FAILED | 使用安全校验提示，不依赖后端 message 分支，不直接渲染原始字段错误 |
| 503、超时、断网、无法确认的服务异常 | 呈现原安全错误及“注册结果暂未确认，可尝试登录核实”，保留表单，不自动重放注册请求 |
| 其他错误或未识别错误码 | 沿用统一安全反馈与脱敏日志，提供可恢复操作，不建立会话 |
| 主动取消、卸载取消、过期响应 | 静默或忽略，不覆盖新页面、新邮箱或新操作的反馈 |

数据库写入失败不消费验证码，数据库成功后 Redis 标记失败也不会撤回已创建的用户。结果未知提示不假定账号未创建，也不要求验证码一定可复用。未知结果下用户点击去登录是已有双向导航的恢复路径。

错误、发码成功通知可以并存。较长的恢复说明按内容增加高度，反馈不能覆盖输入控件。取消 HTTP 请求不能撤销服务端可能已执行的创建行为，返回注册时不得恢复为假成功或自动重试。

请求通过 AbortController 与请求序号等已有生命周期方式隔离。邮箱变更、路由离开和组件卸载后，不应用旧请求结果。清理计时器、动画监听及内存交接，旧登录身份选择状态不能污染注册场景。

## 8. 验证与交付

### 8.1 行为与组合

- 无邮箱注册成功、有邮箱注册成功、验证码前导零，确认请求字段及用途。
- 用户名长度与字符边界，新密码允许字符、首尾空格、全空格、非 ASCII、长度边界，确认密码不一致及修改后的重校验。
- 邮箱为空、有内容但无效、合法邮箱无验证码、修改／清空邮箱、有旧发码请求时修改邮箱，验证请求及反馈一致性。
- 冲突、无效或已消费验证码、错误次数限制、发码各 scope 限流、防重复、网络与服务异常、取消和迟到响应。
- 注册成功不产生会话，回登录的用户名预填、成功通知、密码清空、安全 redirect 保留及认证路由排除。
- 直接访问、刷新、前进后退、转场取消、快速操作、减少动态、键盘焦点与错误播报。
- 现有三种登录、管理员两种身份、401 上下文与安全回跳的关联回归。

### 8.2 视觉与自动化

Vitest 使用 mock，Playwright 使用网络路由 mock，覆盖完整注册到返回登录的用户流程。视觉检查桌面 1366×768、1440×900、1920×1080，手机 320×740、390×844，以及矮屏、放大后的可达性。

按实际 SVG 叶形轮廓测量标题、表单、反馈与导航包含，检查竖排文案位于外侧、真实小叶片可见、动画前后无背景重建闪烁。分别截图完整表单、字段错误和并存反馈状态，动画另行动态检查。跨浏览器、物理手机键盘或原生自动填充只按实际执行记录，不以 Chromium 模拟替代真实设备验证声明。

实施后实际执行 npm ci、npm run check、npm run test:unit:coverage、npm run test:e2e。逐个改动业务逻辑文件完整行覆盖率至少 80%、分支至少 70%，排除项逐文件说明。记录通过、失败、跳过、重试与已知限制，按现行 AGENTS.md 模板交 Claude 独立审核。

本次为纯设计文档，采用链接、格式、契约和范围一致性检查；安装、构建、单元测试、覆盖率与端到端测试不适用。本文不声称注册实现或视觉验收已完成。
