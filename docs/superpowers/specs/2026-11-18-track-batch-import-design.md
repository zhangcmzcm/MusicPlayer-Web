# MGMT-02 批量导入页设计

设计日期为 2026-11-18，核对基线为 `main / 20f3cdc133dcfa94d4562addba2f25d18bda7ac5`。人类已确认浏览器原型 A 及入口与队列操作、进度与恢复、职责与验证三个部分。本文作为书面设计供人类审阅，审阅通过后进入实施计划。

## 1. 目标与交付边界

为当前 ADMIN 身份提供独立批量导入页，一次选择多首音频，按队列顺序逐首调用导入接口，显示发送进度、服务端处理、成功资料、元数据提示及失败恢复。

本切片包含管理列表的真实上传入口、导入路由、同页文件选择与队列、跨页批次状态、幂等重试和权限关联回归。草稿编辑、发布、归档和删除分别按 MGMT-03 至 MGMT-06 交付。导入成功后可进入真实管理列表查看草稿。[歌曲管理任务书](../../tasks/song-management.md)

## 3. 路由、入口与权限

路由为 `/admin/tracks/import`，名称为 `track-import`，懒加载于 BusinessLayout，显式声明 `requiresAuth: true` 与 `roles: ['ADMIN']`。

管理列表标题区域提供“上传歌曲”按钮。导航将当前有效的 q、status、page、size、sort 带入导入路由查询，沿用 `parseManagementQuery` 与 `toManagementQuery`。这些查询仅保存返回列表的上下文。无来源直达和异常返回查询使用默认管理条件，文件导入按自身校验继续。

导入路由声明 `activeNavigation: 'track-management'`。BusinessLayout 根据当前路由名或该归属高亮“歌曲管理”，导航菜单继续读取真实管理路由。导入页的返回按钮、桌面侧栏和手机抽屉中的管理链接均按上述五字段构造返回目标。顶部“音乐”按既有曲库入口导航。

“查看草稿”在已有成功结果时可用，导航到管理列表并以 `status=DRAFT`、page=0 展示，保留有效的排序与页大小，清空搜索关键词，便于浏览新建草稿。“返回歌曲管理”恢复原条件。直接进入导入页的两种返回使用各自默认值。

| 条件                                 | 行为                                                               |
| ------------------------------------ | ------------------------------------------------------------------ |
| 匿名或会话过期                       | 既有守卫进入登录，保留安全站内目标                                 |
| 当前 ADMIN                           | 可选文件、启动、暂停与手动重试                                     |
| 当前 USER                            | 入口隐藏，路由按既有首次／登录回跳与有效来源规则恢复，业务上传停用 |
| 上传返回当前会话 401                 | 统一拦截器清理当前会话并跳转登录，导入状态清理                     |
| 上传返回 403                         | 暂停，显示权限反馈和返回管理入口，保留当前会话                     |
| 会话失效、退出、切换身份或建立新会话 | 清理旧批次及 File 引用，旧结果按原归属忽略                         |

会话角色来自 auth store，后端执行实际授权。[导入权限](../../api/track/import-track.md)与[管理权限恢复](../../features/track-management.md)

## 4. 页面、文件选择与队列展示

页面顶部显示“批量导入”、创建歌曲草稿的说明及返回管理按钮。上传区支持多选和拖入，持续提供添加入口，说明 MP3／FLAC 与每文件 200 MiB。区域下方提示当前标签页的内存生命周期。

队列区域按稳定项目标识展示原文件名、大小、进度或结果及可用操作。成功后补充歌名、艺术家和可展开的提示，长文件名保留完整文本读取方式。桌面采用连续行和独立大小列，窄屏把大小与状态并入文件信息，沿用当前手机导航抽屉。长队列保持主要操作可达，内容纵向滚动。

本地文件校验以扩展名和最大体积为体验依据，扩展名按大小写无关比较，200 MiB 为 209715200 字节。浏览器提供的原 File、文件名与 MIME 保留用于提交，后端校验 MIME、文件魔数和有效音频内容。文件选择控件允许符合规则的其他文件继续加入，校验未通过项单独显示原因并可移除。

选入后等待手动开始。运行时追加的有效文件进入队尾，按当前调度顺序处理。暂停时追加继续等待。全部完成后新增有效文件恢复待开始状态，保留已有结果，等待下一次手动开始。

队列统计按互斥状态计数，显示总项数、已导入、等待及当前存在的处理中、待确认、导入失败和本地校验未通过。元数据提示属于成功项目的补充信息。开始、继续和重试在对应请求或调度已启动时防重复。

## 5. 进度与状态流转

| 文件状态       | 含义与显示                           | 后续动作                             |
| -------------- | ------------------------------------ | ------------------------------------ |
| 等待           | 文件已通过本地校验，尚未发送         | 运行时按顺序发送，可移除             |
| 本地校验未通过 | 格式或体积校验失败                   | 移除或重新选择文件，其他有效项可继续 |
| 正在发送       | 有可计算总量时显示 0—100% 发送进度   | 等待发送结束或请求结果               |
| 服务端处理     | 已确认发送完成，显示正在处理         | 等待后端响应                         |
| 已导入         | 取得可关联的合法成功结果             | 保存资料与提示，运行中继续下一项     |
| 导入失败       | 取得本节错误表中的明确文件／请求拒绝 | 保存原因，按对应调度规则继续或暂停   |
| 待重试         | 限流或权限拒绝使当前项等待手动恢复   | 保留原项与原键，手动重试             |
| 结果待确认     | 传输或服务异常等导致最终结果未确认   | 暂停并保留原文件、原键，手动核对     |

发送进度缺少总量或无法计算时显示不定量的导入反馈。处理中不生成百分比或预计剩余时长。只有传输确认完成后进入处理中，合法响应也可直接结束当前项。显示的发送百分比在实际发送结束前保持小于 100%。

批次状态表达待开始、运行中、完成当前项后暂停、已暂停、已完成。单次运行最多一个发送或处理中的请求，追加和移除等待项均不会改变当前请求关联。

主动暂停后当前请求继续到成功、失败或待确认终态，随后按剩余项进入暂停或完成。请求尚未结束时返回本页，页面准确展示当前项及暂停意图。等待当前项结束期间保持防重复控制。

## 6. 错误恢复与手动调度

| 响应或失败                                     | 当前项处理                           | 批次行为与恢复                                                   |
| ---------------------------------------------- | ------------------------------------ | ---------------------------------------------------------------- |
| 200／201，READY 且关联正确                     | 已导入，记录歌曲与提示               | 当前处于运行状态时继续下一项                                     |
| 413 UPLOAD_TOO_LARGE                           | 导入失败，显示文件过大               | 继续下一项，修正文件后作为新项选择                               |
| 415 UNSUPPORTED_AUDIO_FORMAT                   | 导入失败，显示格式不支持             | 继续下一项，检查或更换文件                                       |
| 422 AUDIO_METADATA_INVALID                     | 导入失败，显示音频损坏或缺少有效时长 | 继续下一项，检查或更换文件                                       |
| 400 VALIDATION_FAILED                          | 记录请求异常                         | 暂停，保留结果和等待项，管理员确认后可继续等待项                 |
| 403 FORBIDDEN                                  | 待重试，显示管理员权限提示           | 暂停，提供当前项手动重试和返回管理入口                           |
| 409 IMPORT_CONFLICT                            | 记录导入标识冲突                     | 暂停并保留该项，管理员可继续等待项，重新选择文件构成新的导入意图 |
| 409 IMPORT_IN_PROGRESS                         | 结果待确认，显示服务端仍在处理       | 保留原文件和原键，稍后手动重试                                   |
| 429 TRACK_IMPORT_RATE_LIMITED                  | 待重试，显示频率限制                 | 暂停并保留原项和原键，等待管理员手动恢复                         |
| 503 MEDIA_STORAGE_UNAVAILABLE                  | 结果待确认                           | 暂停，同键同文件手动重试                                         |
| 503 MEDIA_IMPORT_STORE_UNAVAILABLE             | 结果待确认                           | 暂停，同键同文件手动重试                                         |
| 503 MEDIA_OBJECT_CLEANUP_FAILED                | 结果待确认                           | 暂停，同键同文件手动重试                                         |
| 超时、断网、成功正文异常、其他未明确结果的错误 | 结果待确认，采用集中安全文案         | 暂停并保留关联，手动重试                                         |
| 当前会话 401                                   | 按全局会话失效处理                   | 清理旧批次并进入安全登录恢复                                     |
| 由会话清理触发的主动取消或旧请求回包           | 按原归属忽略                         | 旧调度终止，资源清理                                             |

文件层面的 413／415／422 继续规则来自本轮产品确认，接口本身仅处理单项。400 的暂停用于避免连续发送异常请求，属于客户端批次恢复规则。403 与 429 的手动重试仍使用原项。标识冲突被保留为失败记录，管理员的继续操作推进尚未发送的项。

待确认项或待重试项是当前暂停点。恢复时先重试该项，取得成功或明确文件失败后保持暂停，由管理员点击继续处理后续项。再次出现待确认、限流或权限拒绝时保持对应反馈。重试携带相同 uploadId、原 File 与原文件名，后端以 SHA-256 判定内容。

导入频率额度、窗口和 Retry-After 具体规则尚未写入当前契约。首版采用安全限流文案与手动恢复，实际返回的有效等待信息作为恢复提示展示。精确额度和倒计时以契约补充为依据。既有通用错误映射覆盖其余 HTTP 状态与网络失败，用户看到集中映射的安全文案。[导入响应与幂等](../../api/track/import-track.md)

## 7. 跨页、关联与会话生命周期

Pinia 持有当前标签页和当前 ADMIN 会话的批次。每个新增项获得独立 UUID，作为 uploadId 及稳定队列标识。异步回包同时关联项目和本次请求尝试，队列移除或追加后继续写入原项目。

离开导入页先标记暂停后续调度，当前请求由持续存在的导入状态完成并保存终态。导入页返回后展示真实状态并等待手动继续。批次数据包含等待项、当前项及恢复所需的原 File／文件名／uploadId、成功结果、错误和提示。成功或明确失败项保留展示资料与标识并释放用于发送的 File，待确认和待重试项持续持有恢复材料。

刷新或关闭会丢失内存文件和批次关联，页面已有明确说明。管理列表为已存在歌曲提供人工核对线索，逐项结果以原返回或保留原键与原文件的重放为依据。重新选择的文件属于新的导入意图。[已确认批次生命周期](../../tasks/song-management.md#切页与会话生命周期)

会话变化的监听及时停止旧调度并取消旧传输，释放 File 引用。每次发送前、进度更新和响应写入时核对当前会话对象、ADMIN 角色与 revision。监听以响应式会话及角色为基础，revision 在动作边界再次比较。发生代际失配时结束旧调度的运行状态，旧回调无法恢复旧批次。

请求单次上传使用 600000ms 预算，覆盖发送和同步服务端处理。达到预算后进入结果待确认。页面导航的暂停和会话清理的取消分别遵循上述生命周期，服务器实际结果通过合法响应或原键重试确认。

## 8. 接口与字段消费

业务请求使用 `POST /api/v1/track-imports`，统一业务 HTTP 负责 Bearer、ProblemDetail 与当前／旧会话 401 边界。FormData 仅提交 uploadId 和单个 file，浏览器生成 multipart boundary。标题、艺术家和专辑由后端标签提取。[接口契约](../../api/track/import-track.md)

| 字段或判断                   | 当前用途与合法形态                                      | 缺失、null、边界或异常处理                                                                       | 依据                                  |
| ---------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------- |
| 请求 file                    | 原 File、原名，MP3／FLAC，最大 209715200 字节           | 文件选择按类型与体积给出本地反馈，后端验证文件内容                                               | API 请求参数，本轮文件规则            |
| 请求 uploadId                | 每个新项的 UUID，同项重试沿用                           | 生成失败时显示客户端错误并停止该项发送，保留已选数据                                             | API 幂等规则、客户端运行              |
| 客户端 timeout 配置          | 导入局部 600000ms                                       | 超时保留原关联并暂停                                                                             | 本轮确认、客户端恢复                  |
| 进度 loaded／total           | 浏览器提供的有效进度数据                                | 缺少或异常总量使用不定量反馈，进度展示不决定成功                                                 | 客户端运行、发送与处理确认            |
| HTTP 200／201、顶层 status   | 初次与重放成功均要求 READY                              | 非预期成功形态进入待确认并保留原键                                                               | API 成功与幂等                        |
| 响应 uploadId                | 与当前尝试的 UUID 关联                                  | 缺失、null 或不匹配进入待确认                                                                    | API 关联、客户端写入归属              |
| track.id                     | 正整数 Long，最大 9223372036854775807，精确十进制字符串 | 缺失、null、字符串伪装、非整数或越界进入待确认，支持等价整数表示                                 | API 歌曲结果、既有 Long 消费规则      |
| importId                     | 导入记录资料，合法值精确保留                            | 当前确认采用 uploadId 与 track.id，展示异常可降级为未知                                          | API 资料、响应消费规则                |
| title／artistName            | 成功结果展示                                            | 正常显示原值，缺失、null、空或类型异常使用既有安全展示降级                                       | API 展示字段、AGENTS 响应消费         |
| metadataWarnings             | 空数组或已知警告数组，可与成功共存                      | 已知值映射中文，未知值给通用核对提示，缺失或异常形态给提示信息读取异常反馈，合法歌曲结果仍计成功 | API 警告、响应展示降级                |
| cover                        | 导入资产对象或合法 null                                 | 当前文件行使用类型图标，封面资料按用途消费                                                       | API 成功响应，区别于列表封面 URL 资料 |
| 其他歌曲与资产字段、新增字段 | 沿契约存在，当前操作仅消费所需资料                      | 无关展示信息安全降级或忽略，后续编辑流程重新读取当前资料                                         | AGENTS 响应消费、切片边界             |

成功业务结果为创建草稿，200 重放返回已有导入结果。当前页面确认所需的是 READY、请求关联与可用精确歌曲 ID，后续编辑或状态操作按对应切片重新读取当前歌曲。导入响应中的音频和封面为资产资料，Long 转换复用已有精确解析方式。

## 10. 验证与验收

### 单元与组件

- 文件扩展名与 200 MiB 边界，混合有效／无效文件，长文件名和真实可计算／不可计算进度。

- 原 File、文件名与 uploadId 重试保持关联，超时或旧尝试的迟到回调被忽略。
- 当前项未结束时离页、返回或继续追加，当前项取得终态后后续保持暂停，返回后手动继续。
- 当前会话 401、普通 403、旧响应、同 Token 新会话与请求进入传输前切会话的保护，旧 File 不随新会话发送。
