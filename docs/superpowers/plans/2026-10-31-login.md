# 登录流程实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> 本项目按已指定的 Codex 实现、Claude 独立审核执行；本计划由当前 Codex 会话原生执行，不自行另设实现或审核子 Agent。若所列执行技能不可用，明确报告，不以不存在的技能冒充执行。

**Goal:** 建立必要前端工程，交付三种登录方式、管理员身份选择、会话管理及配套验证。

**Architecture:** Vue 路由页面编排步骤，受控组件呈现表单和身份叶片，composable 管理页面交互，Pinia 管理共享会话与认证动作。统一 Axios 实例封装请求、错误转换和受保护请求的 401 通知；登录业务错误不触发登录重定向。

**Tech Stack:** Vue 3、JavaScript、Vite、Vue Router、Pinia、Axios、Element Plus 全量引入、Vitest、Vue Test Utils、jsdom、Playwright、ESLint、Prettier。

**Spec:** `docs/superpowers/specs/2026-10-31-login-design.md`，已收到第 2 轮文档审核 `accepted`，设计基线 `24ce0c5`。

## Global Constraints

- 一个交付任务为必要脚手架与登录流程；注册、找回密码、歌曲列表业务均不实现，不建立假入口和假路由。
- 本切片不实现登录／注册翻面转场，仅落场景外壳、背景微动与登录最终姿态；管理员身份选择动效属于本切片。翻面及注册姿态随注册切片接入，不写不可达的动画分支。
- 桌面白叶中心位于视口宽度 38% 处，即相对中线左移 12%；表单约 340px 宽，叶片尺寸根据真实内容调整。白叶饱满，叶尖朝右上、叶柄朝左下；不以设计讨论中的 A/B 编号作为实现依据。
- 登录外侧右侧留白中竖排“一叶清新”“一曲自在”两列，从右列向左列阅读，整体垂直居中。该文字定位描述为完整依据，不依赖聊天截图、临时附件或本地草图存档。
- 手机表单与白叶居中，隐藏外侧装饰文案；支持至少 320px 宽与矮屏滚动。现代 Chrome、Edge、Firefox、Safari 及手机浏览器，不兼容 IE。
- 原生 CSS 与 `<style scoped>`；Element Plus 全量引入；中文，无 i18n；主叶片和输入中的表单稳定，减少动态设置下停止空间与循环运动。
- 悬停绿色加深、链接下划线；键盘绿色外描边；加载禁用降饱和；校验低饱和暗红并附文字；状态过渡约 150ms。
- Node.js 锁定 `22.23.4`，`.nvmrc` 写该版本，`engines.node` 为 `>=22.23.4 <23`。这是已核实的 LTS 安全补丁版本，不修改机器全局 Node 安装。验证应使用符合版本的运行时。
- npm 管理依赖，安装使用 `--save-exact`，同步提交 `package-lock.json`。Vite `8.3.5`、`@vitejs/plugin-vue` `6.0.10`、Vitest 与 coverage-v8 均为 `5.0.5`；其他规定依赖安装前核实 engines 与 peerDependencies，锁定所选稳定版本。
- Token 与会话只存 `sessionStorage`，票据仅内存；不新增刷新 Token、远程会话查询接口或真实后端测试。
- 只读 `docs/api/`、`docs/design/`、`example/`、`CLAUDE.md`；人类尚未提交的主题修改保留原样，不混入本任务提交。
- 覆盖率阈值：本次新增或修改源码行至少 80%，分支至少 70%。无 `.ts`、真实秘密、调试残留、死代码或占位实现。

版本依据：[Node.js 22.23.4 发布说明](https://nodejs.org/en/blog/release/v22.23.4)、[Vite 环境要求](https://vite.dev/guide/)；工具版本已通过官方 npm 元数据核实。

## Review Focus

1. 旧请求在卸载、重新登录、清会话之后才完成：不能恢复旧 Token、票据或表单错误；任务 3、4 用可控 Promise 断言。
2. 浏览器后台节流、切换登录方式和更换邮箱：倒计时按截止时刻恢复，不因切换方式绕过同邮箱冷却；任务 4 用可控时钟断言。
3. sessionStorage 被禁用、内容损坏或写入失败：不崩溃、不宣称会话已持久化，不将内部存储错误暴露给用户；任务 1、3 验证。
4. 回跳包含外部域名、反斜线、协议相对地址、登录自循环、未知路由：不能开放重定向或导航循环；任务 3 验证。
5. 中文输入法组合期间 Enter、验证码以零开头、错误文字使表单变高：不误提交、不丢字符、不超出白叶；任务 4、5、6 验证。

### Task 1: 工程配置、错误与会话基础

**Files:** 新增根配置、`src/test/setup.js`、`src/test/factories.js`、`src/utils/errors.js`、`logger.js`、`session.js`，及对应 `*.spec.js`。

**Interfaces:**

- `ApiError({ code, status, retryAfter, scope })`：`Error` 子类，`detail` 只能是集中映射后的安全文本，`retryAfter` 为有效秒数或 null。
- `getErrorMessage(error)`：按 code 优先、HTTP 状态兜底，返回安全中文。
- `reportError(error)`：只记录经过白名单处理的错误类别、状态和允许的 code；不得记录请求、响应体、URL 查询或用户输入。
- `readSession(storage, now)`、`writeSession(storage, session)`、`clearSession(storage)`：校验契约会话结构与过期时间；存储异常转换安全错误，不静默声称持久化成功。读取损坏数据返回空会话并尝试清除。

- [ ] 核实剩余依赖与 Node engines；使用匹配的本地便携运行时或已安装运行时，不改全局 Node。不在本步骤建立业务占位页。
- [ ] 建立全部约定 npm scripts、ESLint Vue flat config、Prettier、Vitest jsdom；覆盖率 include `src/**/*.{js,vue}`，只排除测试和测试辅助。设 lines 80、branches 70；入口或纯装配文件若不能覆盖，需要最终报告列明，不暗中扩大排除。
- [ ] 先写错误与会话测试：未知 code 不显示原始 detail；401/403/404/409/429/5xx/超时/断网文案各有意义；损坏 JSON、已过期会话、非法结构、存储读写异常；正常恢复保留服务端用户 ID 类型。
- [ ] 执行 `npm run test:unit -- src/utils/errors.spec.js src/utils/session.spec.js`，确认缺少实现导致失败，再实现上述接口。
- [ ] 重跑同组测试并执行 `npm run lint`；预期全部通过、零警告。保存 lockfile，按本任务文件清单创建中文提交，不包含主题修改。

### Task 2: HTTP 与契约 API

**Files:** `src/api/http.js`、`src/api/auth.js`、`src/api/http.spec.js`、`src/api/auth.spec.js`、`.env.example`、`vite.config.js`。

**Interfaces:**

- `http`：单个 Axios 实例，baseURL 来自 `VITE_API_BASE_URL`，默认 `/api/v1`，超时 15000ms。
- `configureAuth({ getSession, onUnauthorized })`：初始化时绑定会话读取和失效回调，避免 HTTP → store → HTTP 循环导入；测试可重新配置。
- `login(payload, { signal })`：原样发送契约必要字段，返回校验后的 `AUTHENTICATED` 或 `ROLE_SELECTION_REQUIRED` 响应。
- `sendLoginCode(email, { signal })`：只发送 `{ email, purpose: 'LOGIN' }`，返回校验后的 purpose 和 expiresAt。

- [ ] 写 adapter mock 测试：四种 loginType 的精确请求体，发送 purpose，成功响应结构，非法 200 响应转安全错误，绝不访问网络。
- [ ] 写 HTTP 测试：有效 Bearer 注入；公开认证请求不注入；受保护 401 清会话通知；公开登录 401 不通知；403 不清会话；有效／非法 Retry-After；取消与网络错误；未知错误不泄漏请求体。
- [ ] 先运行 `npm run test:unit -- src/api` 确认失败，再实现 API 与拦截器。公开请求用明确配置标记，不依赖 URL 子串猜测。
- [ ] 写环境模板：`VITE_API_BASE_URL=/api/v1`，`VITE_API_PROXY_TARGET` 留空并说明需要本地配置；Vite 只在提供代理目标时配置 `/api` 代理。配置中不硬编码后端域名。
- [ ] 重跑 API 测试及 lint，预期全部通过，提交本任务。

### Task 3: 会话状态、认证动作与导航

**Files:** `src/stores/auth.js`、`src/utils/redirect.js`、`src/router/guards.js`，各自同目录测试；路由实际注册在任务 5 接入。

**Interfaces:**

- `useAuthStore()`：公开 `session`、`roleSelection`、`pending`、`error`、`isAuthenticated`，动作 `restoreSession()`、`authenticate(payload, { signal })`、`selectRole(role, { signal })`、`clearSession()`、`clearRoleSelection()`。
- `resolveSafeRedirect(router, candidate)`：返回实际存在且非登录／404 的站内 fullPath 或 null；不发明默认业务路径。
- `createAuthGuard(auth)`：读取 route meta 的 requiresAuth／roles；角色不满足给出安全提示并阻止导航，不借隐藏入口替代后端授权。

- [ ] 先写 store 测试：普通成功保存会话，管理员第一阶段不保存会话，选择 USER／ADMIN 的票据请求及响应，pending 防重，错误恢复，票据到期／失效，存储失败不假成功。
- [ ] 添加竞态测试：clearSession／取消之后旧 Promise 返回不能建立会话；并发受保护 401 不能循环导航；旧 Token 请求的失败不能清除新建立的会话。
- [ ] 用隔离内存路由测试守卫和安全回跳，包括外链、协议相对路径、反斜线、编码后的危险路径、未知路由、自循环。测试专用目标不进入产品路由表。
- [ ] 执行 `npm run test:unit -- src/stores src/router src/utils/redirect.spec.js` 确认失败，实现后再运行，预期全部通过；任务结束提交。

### Task 4: 登录交互、验证码冷却与表单组件

**Files:** `src/composables/useLogin.js`、`src/components/auth/LoginForm.vue`、对应测试。

**Interfaces:**

- `useLogin(auth)`：返回 form、loginType、busy、sending、error、codeNotice、sendRemaining、loginRemaining、rules，以及 `changeMethod(type)`、`submit(formRef)`、`sendCode(formRef)`、`restart()`。所有时间按截止时刻计算，卸载清理。
- `LoginForm`：props 接收 modelValue、loginType、rules、busy、sending、倒计时与安全提示；emit `update:modelValue`、`method-changed`、`submit`、`send-code`，不访问 store 或 Axios。
- 父组件处理校验与动作，表单组件提供 Element Plus 表单引用的必要校验能力；不把整套业务写入展示组件。

- [ ] 先写 composable 测试：默认 EMAIL_PASSWORD，三种精确 payload，邮箱规范化，密码原样，code 前导零，切换清敏感字段且保留邮箱，不因切换重置同邮箱冷却。
- [ ] fake timers 覆盖 60 秒发送冷却、契约 expiresAt、Retry-After、EMAIL_COOLDOWN／EMAIL_DAILY_LIMIT／IP_RATE_LIMIT，修改邮箱不解除 IP 限制，后台跳时按截止时刻计算。
- [ ] 写组件测试：Element Plus rules 阻断空值及长度边界，密码可见性，发送只校验邮箱，提交期间全部相关操作禁用，IME Enter 不提交，普通 Enter 提交，展开其他两种方式并选中收起。
- [ ] 写取消测试：卸载后请求完成不更新状态；旧邮箱的发送结果不能覆盖新邮箱提示；API 明确成功后才展示发送成功与冷却。
- [ ] 执行 `npm run test:unit -- src/composables src/components/auth/LoginForm.spec.js` 确认失败，再实现；重跑通过并 lint 后提交。

### Task 5: 登录场景、管理员身份选择与真实页面
