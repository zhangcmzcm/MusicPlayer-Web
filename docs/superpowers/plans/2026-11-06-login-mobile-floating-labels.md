# 登录页手机一屏与浮动标签实施计划

> 执行方式沿用本对话Codex顺序实现、Claude独立审核、人类最终确认。执行阶段按计划逐项验证与提交，步骤使用复选框记录实际进度。计划目前供人类审阅。

**目标** 让320×740和390×844手机视口容纳常规登录状态及未来导航容量，并为各端四类登录字段提供浮动标签。

**架构** LoginForm通过现有Element Plus真实label、输入关联与CSS状态完成浮动展示。AuthScene负责手机场景与装饰，LoginView负责标题及反馈密度，关联行为由组件测试和浏览器几何测试验证。

**技术栈** Vue 3、JavaScript、scoped CSS、Element Plus、Vitest、Vue Test Utils、Playwright。使用现有锁定依赖。

**设计依据** [已获人类确认的设计](../specs/2026-11-06-login-mobile-floating-labels-design.md)，提交 `ee0e021`。上一维护任务基线 `0a30ff7` 已获实现审核accepted，本轮另行交付。

## 全局约束

- 手机一屏基线为320×740、390×844 CSS视口，默认字体、100%缩放、软键盘收起。覆盖三种登录、两行字段错误、常规接口反馈、展开方式与未来两行文字。
- 长恢复说明、软键盘、系统大字、200%浏览器缩放和更矮窗口采用自然整页滚动，全部文字、焦点和操作可达。
- 手机品牌16px，图形约24×28px，内容起点参考112px，标题右移参考12px，底部参考20px。反馈区64px，文字12px／18px行高，允许长内容自然增长。
- 桌面沿用人类调整的1188px叶宽与左移12%落点。手机叶片参考950×1080px、顶部-220px，按实际轮廓验证调整。
- 保留三个小叶片、风线、渐变及轻微动画，减少动态模式按既有规则呈现。品牌、叶片、表单及装饰共同截图验收。
- 用户名、邮箱、密码、验证码各端统一浮动标签，输入和主按钮高度46px。字段错误继续保留42px容量，主控件状态变化容差为1 CSS px。
- 未来辅助行和底部各22px，仅测试侧注入纯文本容量探针。产品入口随对应业务交付。
- 本轮文件限定为认证场景、表单、视图、关联测试和功能文档。依赖、API、权限、Token、路由、useLogin及auth store均为关联回归对象。
- 最终实际执行四条验证命令，逐文件完整源码行覆盖率至少80%，分支至少70%。

## 当前编辑与工作区归属

人类当前编辑为AuthScene桌面宽1188px、手机宽950px／顶部-130px／高1150px，以及LoginView手机反馈区88px。实施基于该工作区继续调整，同文件最终diff明确区分继承尺寸与本轮设计变更。已有三个桌面邮箱密码布局用例通过。

`docs/tasks/login-follow-up.md`属于前一任务文档。每次提交显式指定文件，记录未提交内容归属。正式实施前重新核对git diff，遇到额外编辑先核实。

## 重点回归风险

1. 含首尾空格的密码、程序预填或自动填充与标签重叠，任务1验证真实字符串长度，任务3记录浏览器自动填充实测。
2. 验证码组内的发送按钮、密码显隐图标影响标签或输入宽度，任务1与任务2验证关联、焦点和稳定几何。
3. 全局label的重要性规则覆盖局部定位，标签点击或读屏名称失效，任务1检查真实for／id和语义定位，任务2检查实际位置。
4. 320px下两行字段错误、并存通知和未来导航压出页面，任务2保留原断言并补手机一屏矩阵。
5. 场景缩短让原装饰消失或盖住控件，任务2验证节点保留、可见区域、截图与减少动态。

## 任务1 完成各端浮动标签

**文件** LoginForm.vue、新增LoginForm.spec.js、关联LoginView.spec.js。

**接口** 现有组件接口继续由父页面消费。每个字段容器具有floating-field类，实际字符串非空时添加has-value，判断使用字符串长度。CSS结合focus-within、has-value、Element Plus原有is-error和禁用状态控制标签。

- [ ] **步骤1 补组件红测。** 用真实Element Plus挂载LoginForm，modelValue包含email、username、password、code四个字符串，事件回写模型。对三种方式分别断言真实label的for等于对应input.id，用户名／邮箱／密码／验证码可通过可访问名称定位，两个表单实例的输入ID各自唯一。
- [ ] **步骤2 补展示与行为用例。** 断言空值无has-value，输入及程序预填添加has-value，清空后移除。密码为普通空格时仍视为已有输入，保留原值。校验失败保留错误及真实关联，pending禁用仍可显示既有值。既有切换清理、发码与密码显隐由页面回归覆盖。
- [ ] **步骤3 运行定向测试。** 执行 `npm run test:unit -- src/components/auth/LoginForm.spec.js src/views/login/LoginView.spec.js`，记录新类或关联断言的真实失败。
- [ ] **步骤4 实现字段类与标签定位。** 保留el-form-item的label与prop，复用生成ID，移除与框内标签重叠的可见placeholder。局部CSS将原label绝对定位到输入框内，初始约13px淡灰，浮起约11px并用衬片覆盖边框。聚焦为主题绿，错误为原错误色，已有内容失焦保留浮起，空值且无错误失焦返回框内。
- [ ] **步骤5 保留完整交互容量。** 输入46px、错误42px合计88px字段内容区，标签浮起脱离布局占高。过渡约150ms，减少动态时直接呈现最终状态。验证码发送按钮宽106px，密码显隐、倒计时、中文输入法与原验证接口纳入回归。
- [ ] **步骤6 核对CSS与原生事件。** 以真实label点击聚焦测试确认层级和点击区域，使用当前模型值及原生输入事件同步展示。自动填充行为在任务3由浏览器验证，测试报告区分程序赋值与原生自动填充证据。
- [ ] **步骤7 重跑定向测试与lint。** 同步骤3命令全部通过，执行 `npm run lint`。组件测试断言用户可见语义，几何与过渡位置交任务2验证。

## 任务2 完成手机一屏与装饰关联布局

**文件** AuthScene.vue、LoginView.vue、e2e/login.spec.js，必要局部样式落在LoginForm.vue。

**消费接口** 任务1的floating-field／has-value，既有stableBoxes、expectStable、leafOverflow、反馈与未来导航容量结构。

- [ ] **步骤1 扩展手机矩阵。** 320×740与390×844各覆盖EMAIL_PASSWORD、USERNAME_PASSWORD、EMAIL_CODE。按初始、聚焦、已填、失焦、两行校验、常规接口失败、发码通知、展开方式及未来容量采样，断言页面scrollWidth和scrollHeight均在视口内，控件状态差值仍≤1px。
- [ ] **步骤2 分离常规与长反馈验收。** 手机一屏矩阵通过mock提供明确的INVALID_CREDENTIALS等常规错误，验证码先产生真实codeNotice，再提交登录。原有网络／503恢复用例继续验证完整文案、冷却及可恢复性，长内容允许整页滚动。每类反馈分别保留断言。
- [ ] **步骤3 补浮动几何与语义测试。** 用 `getByLabel` 定位并点击真实label，检查empty／focus／filled／blur／error状态的标签相对输入边框位置。采用减少动态或等待过渡完成，测量标签及控件DOMRect，断言浮起后标签跨越上边框，输入和按钮保持稳定。验证码和密码显隐辅助控件分别覆盖。
- [ ] **步骤4 复用容量与轮廓断言。** 未来两行文本仍仅通过page.evaluate注入已有空结构。leafOverflow增加真实label的边界检查，保留标题、输入、按钮、错误和探针检查。桌面三视口、三方式沿用1188px叶宽回归。
- [ ] **步骤5 补装饰验证。** 保留三个小叶片SVG、风线及aria-hidden语义，检查手机边缘至少有装饰叶片实际可见，截图确认其位于主白叶外侧且避开文字。减少动态模式下验证既有背景运动与新标签过渡的处理。为装饰增加稳定标识仅在定位确有必要时使用。
- [ ] **步骤6 运行布局红测。** 执行 `npm run test:e2e -- --grep 'floating|mobile_one_screen|stable_layout|fit_layout'`，记录当前手机超高或标签定位的实际失败。
- [ ] **步骤7 实现A方案。** 手机品牌16px、图形24×28px，内容顶部参考112px、标题偏移12px、反馈区64px、底部20px。常规反馈12px／18px，两行原错误加通知及间隔预留完整。保留桌面1188px叶宽，按950×1080px／顶部-220px起点验证手机叶形。
- [ ] **步骤8 调整装饰与短屏降级。** 按紧凑后的场景检查原三个装饰的边缘位置、背景风线、管理员两种身份布局、focus描边和无横向溢出。长内容及矮视口以整页滚动访问，CSS数值按设计允许范围微调并记录。
- [ ] **步骤9 重跑步骤6至通过并查看截图。** 覆盖正常／错误／展开／未来文本和身份选择，保留1px阈值。若基线容量无法满足，携实际测量交人类裁定。
- [ ] **步骤10 提交实现明确文件。** 两任务共用LoginForm等文件，合并为一个通过定向验证的实现提交，中文信息为 `fix: 完善手机一屏布局与浮动标签`。提交前核对人类尺寸调整的归属与索引。
