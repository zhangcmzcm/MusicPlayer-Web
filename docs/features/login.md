# 登录流程

## 目标与边界

交付 `/login` 的邮箱密码、用户名密码、邮箱验证码登录，以及管理员认证后的本次身份选择。包括第一份前端脚手架、统一 HTTP、会话、路由基础、测试和功能文档。

不包含注册、找回密码、歌曲列表或其他音乐业务；不创建其占位入口。当前登录成功显示服务端返回的用户名和本次身份，不跳转到尚未实现的歌曲列表。

设计依据：`docs/superpowers/specs/2026-10-31-login-design.md`；任务与进度：`docs/superpowers/plans/2026-10-31-login.md`。主题与样例仅作为配色和气质参考，实际构图为人类已确认的方案。

## 路由与场景

- `/` 重定向 `/login`。
- `/login` 是 `AuthScene` 父路由布局的子路由。背景、风线、白叶和外侧竖排文案由父布局持有，子页面通过嵌套 `RouterView` 渲染。
- 未知地址进入独立 404，可返回登录。
- 未来注册页加入同一父路由，不重新挂载场景。本次只实现登录姿态与管理员身份动效；不包含注册姿态或不可达的翻面动画。

## 接口依赖

| 操作               | 接口                                                  | 契约引用                      |
| ------------------ | ----------------------------------------------------- | ----------------------------- |
| 三种登录及身份选择 | `POST /api/v1/auth/login`                             | `docs/api/auth/login.md`      |
| 发送登录验证码     | `POST /api/v1/email/send-code`，固定 `purpose: LOGIN` | `docs/api/email/send-code.md` |

请求经 `src/api/http.js` 的单一 Axios 实例发送，超时 15 秒。公开认证请求不带已有 Bearer；受保护请求由统一层注入当前 Token。响应必须满足契约结构，否则显示安全错误，不假定成功。

## 权限与会话

- 仅 `AUTHENTICATED` 建立会话，身份来自响应中的会话用户，不取 URL 或隐藏表单字段。
- Access Token、tokenType、expiresAt、会话用户保存在 Pinia 和 `sessionStorage`；同一标签页刷新恢复。以标签页会话存储语义为准，浏览器恢复会话或复制标签页的行为由浏览器决定，不作为后端授权保证。
- 过期、损坏或非法会话清除；浏览器存储不可用时显示安全错误，不声称已保存登录状态。
- 管理员第一阶段仅保留内存票据，不建立会话。刷新不恢复票据；选择用户或管理员后由后端签发本次身份。
- 票据过期或 `LOGIN_TICKET_INVALID` 返回登录步骤；403 展示权限错误，不提升身份。
- 登录凭据 401 留在表单；受保护请求 401 清凭据并跳转登录。旧 Token 请求的延迟 401 不能清除新会话。无自动续签或登录重试。
- 回跳只接受真实站内路由；拒绝外部地址、协议相对地址、反斜线、控制字符、未知路由和登录循环。不为了测试增加产品业务路由。

## 操作与状态

默认邮箱密码。小字“其他登录方式”展开另外两种选项，选择后收起。邮箱在邮箱模式间保留；切换清空密码、验证码和旧错误。密码支持粘贴、自动填充、显示隐藏；Enter 提交，中文输入法组合期间不提交。

Element Plus rules 校验邮箱格式及 120 字符上限、用户名 3–80、密码 8–128、验证码 6 位数字。密码不裁剪空格，验证码作为字符串保留前导零。校验失败不发请求。

验证码发送前只校验邮箱，成功后按该邮箱冷却 60 秒；同邮箱冷却不因切换登录方式重置。429 按 `Retry-After` 暂停操作，发送 IP 限流不会因更换邮箱解除。倒计时按截止时刻计算以适应后台节流；验证码发送提示依服务端 `expiresAt` 到期清除。

校验、登录、发送期间禁用相关交互。管理员票据到期、页面卸载或重新登录会取消请求或丢弃过期结果，不由延迟响应恢复旧状态。

各类失败有单独安全文案：认证、校验、权限、资源不存在、冲突、限流、邮件发送、服务不可用、超时与网络失败。只根据 code／HTTP 状态分支，不展示原始 detail、堆栈或内部路径。统一日志仅保留白名单错误类型和数字状态，不记录请求体、Token、密码、验证码、票据或邮箱。

本切片没有列表请求，不涉及列表的空态或分页；登录等待输入、加载、错误、身份选择和真实成功均有对应呈现。

## 已确认视觉与可访问性

- 嫩叶绿背景，饱满白叶，桌面向中线左侧偏移约 12%；表单宽约 340px，叶片随内容及错误提示调整。
- 右侧留白两列竖排“一叶清新”“一曲自在”，从右列向左列读，手机隐藏。
- 手机居中，矮屏可滚动，不横向溢出；正文为真实 HTML，不用 SVG 绘制业务表单。
- 身份选择时大白叶退场，风带来白色用户叶与淡绿色管理员叶；桌面并排、手机上下。到位后可选，加载时两项禁用，限流显示剩余时间。
- 绿色悬停及焦点、文字下划线、低饱和暗红校验文字和边界；约 150ms 状态过渡。
- 标签与输入关联，按钮使用原生语义；步骤变化把焦点移至标题。减少动态效果时关闭循环和空间运动，身份选择直接可操作；动态设置变化时及时启用身份选择。
- 不渲染暂未可用的注册和忘记密码入口。未来翻面方案已保存在设计文档，随注册切片实现。

## 修复记录

### 未绑定邮箱用户的登录修复

成功会话的 `user.email` 允许为 `null`，与 `docs/api/auth/register-user.md` 中邮箱可选、未绑定时返回 null 的用户模型一致。原会话校验误将邮箱限制为字符串，导致管理员完成任一身份选择后，合法的 `AUTHENTICATED` 响应被前端报为 `INVALID_RESPONSE`；登录服务并不因此失败。

本次只修正该字段的类型判断，保留 Token、过期时间、用户身份和响应结构校验；不接受缺失的 email、数字、布尔、对象或数组，不补造空字符串，也不更改后端契约。新增单元测试覆盖两种身份的 API 成功响应、会话保存与恢复及非法邮箱类型；新增浏览器流程覆盖未绑定邮箱管理员选择两种身份并刷新恢复。测试使用自建票据与 Token，不复制真实登录凭据。

修复先由 4 个失败回归用例复现；单行类型判断修正后，定向用例 15/15 通过。随后实际执行 `npm ci`（沿用本次进程的 Clash 7897 代理参数）、`npm run check`、`npm run test:unit:coverage`、`npm run test:e2e`，最终全部退出 0：Vitest 81 通过／0 失败／0 跳过，Playwright 21 通过／0 失败／0 跳过；行覆盖率 95.30%、分支覆盖率 86.54%。没有依赖或样式变更。

首次 `npm ci` 因开发中的 Vite 占用 Windows 原生模块而报 EPERM；确认并暂时停止本项目开发进程后重跑成功，验证前已恢复原 127.0.0.1:5173 开发服务并确认 HTTP 200。原有依赖审计和构建体积提示不变。真实用户复测需重新登录取得新票据，不能重用可能已被后端消费的身份选择票据。

### BLOCK-001 仍需审核方复核的依据

登录文档仅列响应示例，未把注册请求的所有限制声明为所有已有用户的响应不变量。后端当前 `LoginUserResponse` 的 username/email 为 String 字段；`AdminBootstrapInitializer` 直接保存配置值，requiredValue 仅拒空，不转小写，也不复用注册用户名长度/字符集校验。因此，强制拒绝大写响应邮箱或按注册规则限制所有响应用户名，会引入合法管理员被拒的可能。

本轮不修改人类维护的契约，不擅自把旧阻断降为建议。请求审核方依据已更新 AGENTS.md 的“区分请求与响应消费”“无关展示字段可安全降级”复核这部分修复要求；如仍要求更严格的响应值域，请后端维护者明确所有用户来源的响应约束，再据此实现。`user.id` JSON 类型、Z 与 +00:00 的输出范围同样保留为响应契约澄清项；不把当前实现或一个示例升级为通用业务规则。
