# 曲库主页与关联功能任务书

更新日期为 2026-11-14。功能分组与主页定位已经人类确认。

## 用途与交付范围

本任务书梳理曲库主页、全局播放、播放队列、我的收藏、个人中心和歌曲管理之间的关系，记录后端依赖、后续任务边界及建议交付顺序。当前交付物为本文档，后续代码任务由人类逐项选择，每项分别完成设计、实现、验证和独立审核。

曲库主页承担进入项目后的听歌入口。相关账户功能沿用既有任务编号，歌曲管理按独立流程交付。页面布局、播放器形态及各切片的详细交互，在对应任务开始时确认。

## 当前项目与契约基线

前端已有登录、注册、找回密码、会话存储、统一请求层和路由守卫。当前站点根入口转向登录，曲库交付时需接入实际主页和登录成功后的默认落点，继续支持安全站内回跳。AUTH-07 的默认业务落点工作归入 LIB-01。[现有路由](../../src/router/index.js)与[登录后续功能任务书](login-follow-up.md)

现有歌曲与收藏接口使用 Bearer 登录认证。普通用户可见已发布歌曲，管理员登录身份可访问更多状态。统一听歌主页需显式请求 `status=PUBLISHED`，使两种登录身份获得相同的主页歌曲范围。管理能力依据本次登录身份判断，账户最高角色通过个人资料接口读取。[曲库列表契约](../api/track/list-tracks.md)与[当前用户契约](../api/user/get-current-user.md)

本任务书按 `main` 分支、提交 `0660f5fa0e142c707ad93aa4fb4614709ec78ced` 及编写时的工作区文档核对。工作区中的曲库列表契约有未提交更新，三份收藏契约为未跟踪文件。后续切片开工时需确认这些文档的有效版本与后端就绪情况，真实联调结果另行记录。

## 功能与页面衔接

| 功能组         | 页面或交互职责                                               | 主要衔接                                                 |
| -------------- | ------------------------------------------------------------ | -------------------------------------------------------- |
| 曲库主页       | 歌曲信息、搜索、排序、分页、直接播放及歌曲行操作             | 登录默认落点、全局播放器、队列、收藏、个人中心、歌曲管理 |
| 全局播放器     | 当前歌曲信息、播放与暂停、进度拖动、音量、上一首与下一首     | 在曲库、收藏、个人中心和管理等业务页面间持续存在         |
| 播放队列与模式 | 查看队列、添加、移除、调整顺序，支持顺序、单曲循环和随机播放 | 曲库与收藏提供歌曲来源，播放器使用队列切歌               |
| 我的收藏       | 本人收藏分页列表、排序、直接播放与取消收藏                   | 曲库歌曲行同步收藏操作结果，复用全局播放与队列           |
| 个人中心       | 本人资料展示、用户名、密码、邮箱相关流程及退出登录           | 使用已有会话，关联已有 AUTH 任务                         |
| 歌曲管理       | 管理列表、导入、草稿编辑、发布、归档和删除                   | ADMIN 入口，操作结果通过后续读取反映到曲库与收藏         |

曲库、收藏、个人中心和歌曲管理具有独立页面职责。队列作为全局播放交互的一部分，其面板形态随播放器设计确认。账户安全操作与管理操作分别确定路由页面或页内流程，具体地址写入各切片设计。

导航入口随目标功能交付接入。首个主页切片交付可独立使用的曲库浏览能力，播放、收藏及后续页面入口由各自切片接入。每次新增入口同时验证真实导航、刷新、浏览器返回与权限反馈。

### 曲库浏览

- 列表直接展示封面、歌名、艺术家、专辑和时长。专辑、时长、封面按契约接受 `null`，相应显示缺省文案或封面占位。
- 搜索覆盖歌名、艺术家和专辑，使用后端统一关键词查询。排序选项取自 `id`、`title`、`artistName`、`createdAt` 及合法方向，界面文案在主页设计中确认。
- 列表使用服务端分页与精确统计，查询条件改变后按已确认的分页交互重新读取。
- 搜索、分页和排序变化时处理过期请求，加载、空结果、读取失败和重试均有明确界面反馈。
- 封面通过携带认证头的资源请求加载。单张图片加载失败时显示缺省封面，并按错误上下文处理会话失效。[列表契约](../api/track/list-tracks.md)与[封面契约](../api/track/get-track-cover.md)

### 全局播放与队列

- 用户在歌曲行触发播放后，全局播放器显示当前歌曲及播放状态。
- 播放器和媒体实例由业务页面共同使用的应用层承载，路由切换时持续存活。跨组件共享的当前歌曲、队列和播放状态由 Pinia 管理。
- 单曲播放切片交付跨页持续播放、播放与暂停、进度及音量。上一首、下一首和播放模式随队列切片接入。
- 队列切片负责添加、移除、调整顺序与切歌。队列来源、跨分页范围、重复歌曲、随机范围和播放结束规则，在 PLAY-02 设计中集中确认。
- 退出登录或当前会话失效时，清理该会话的播放状态和受保护资源。快速切歌、请求取消及旧会话迟到响应，遵循当前请求与会话的生命周期规则。[现有会话实现](../../src/stores/auth.js)与[音频契约](../api/track/stream-track.md)

### 收藏与个人中心

收藏属于当前登录用户。曲库歌曲行提供收藏交互，收藏页提供本人列表、分页、排序、播放和取消操作。成功写入后同步当前界面中相关歌曲的收藏状态。网络结果未知时，根据接口幂等语义提供恢复操作。[收藏](../api/favorite/favorite-track.md)、[取消收藏](../api/favorite/unfavorite-track.md)与[收藏列表](../api/favorite/list-favorites.md)

个人中心先交付资料读取，再按需求接入改名、改密和邮箱流程。退出登录通过现有会话管理完成。敏感操作中的再次验证、Token 更新和重新登录，沿用已有账户契约与 AUTH 任务边界。[账户任务书](login-follow-up.md)

### 管理员歌曲流程

管理列表负责状态筛选和各管理流程入口。导入生成草稿，草稿编辑负责文本元数据，发布使歌曲进入已发布状态。草稿和已发布歌曲均可归档，已归档歌曲可物理删除。发布、归档、删除提供后果说明和二次确认。[导入](../api/track/import-track.md)、[草稿编辑](../api/track/update-track-draft.md)、[发布](../api/track/publish-track.md)、[归档](../api/track/archive-track.md)与[删除](../api/track/delete-track.md)

## 数据职责与异常处理要求

普通业务请求沿用 `src/api/` 封装，页面负责查询条件和私有展示状态，跨页面播放状态进入 Pinia。展示组件通过 props 和事件协作，播放器媒体资源的创建、取消、切换与释放由播放功能统一管理。

| 场景                       | 对应验收要求                                                                   |
| -------------------------- | ------------------------------------------------------------------------------ |
| 列表加载、空结果、读取失败 | 呈现独立状态，失败后可重试，合法越界页依分页契约处理                           |
| 搜索限流                   | 按稳定错误码反馈，使用 `Retry-After` 提供恢复时机，搜索预算与参数遵守当前契约  |
| 当前受保护会话失效         | 清理当前会话及其播放资源，安全回到登录，旧会话迟到响应通过现有会话代际规则处理 |
| 管理员接口拒绝             | 根据 403 或具体接口的隐藏资源语义反馈，当前身份决定入口可用性                  |
| 图片读取失败               | 回退到缺省封面，真正的会话失效交由统一会话流程处理                             |
| 音频读取失败或传输中断     | 提供可理解的播放失败与恢复操作，保持当前歌曲和用户操作上下文一致               |
| 歌曲归档、删除或并发变化   | 列表、收藏和播放请求按各自最新响应处理状态变化，提供刷新或恢复操作             |
| 收藏写入结果未知           | 利用 PUT／DELETE 的幂等语义，避免响应到达顺序覆盖后续用户意图                  |
| 管理状态冲突               | 按 409 错误码反馈并引导重新读取，发布、归档、删除分别说明后果                  |

错误文案复用集中映射及安全兜底。各切片针对实际消费字段补齐合法 `null`、边界、取消、过期响应和并发场景，校验依据逐项引用接口、产品、安全或客户端运行规则。

## 建议交付顺序

1. LIB-01 先交付真实主页、浏览能力和默认登录落点，形成后续功能的业务入口。
2. PLAY-01 解决浏览器播放链路，形成曲库选歌到跨页持续播放的完整体验。
3. PLAY-02 完善队列与模式，FAV-01 在收藏状态来源确认后接入曲库收藏。
4. FAV-02 形成曲库与我的收藏之间可往返的听歌流程。
5. AUTH-03 提供个人中心，再依需求选择 AUTH-04、AUTH-05 和细化后的 AUTH-06。
6. MGMT-01 建立管理入口，随后依实际维护需求选择导入、编辑、发布、归档和删除任务。

这份顺序用于讨论优先级。账户和管理任务可在人类选择后调整到更早阶段，具体开工仍依据任务依赖和对应设计确认。
